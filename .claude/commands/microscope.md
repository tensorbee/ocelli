# /microscope F-XXX [--working | --completed]

`--working` reviews the uncommitted or worker-branch diff. `--completed` audits
already landed work.

## Repeat until clean. There is no pass limit and that is deliberate.

**One pass is not the rule and never was.** Three things make this
non-negotiable:

- **Every remediation is itself unreviewed work** until a pass has seen it. A
  fix nobody reviewed is exactly as likely to be wrong as the code it fixed,
  and more likely to be written in a hurry.
- **The reviewer must be independent of the author.** A self-review of one's
  own remediation reliably finds nothing.
- **A clean pass is a claim about the tree, not about effort.**

A cap would either land known defects or stall the sprint on a judgement the
cap cannot make. What replaces it is a signal: **report one line per pass**
naming the F-ID, pass number, and defect, smell and nitpick counts. A rising
pass count with changing findings is progress. The same finding surviving three
passes is not, and is worth telling the operator without stopping the loop.

## Severity

| Level | Meaning |
|-------|---------|
| **Defect** | Wrong behaviour, or a claim in prose that is false. Blocks completion |
| **Smell** | Correct but will cause a defect later. Blocks completion |
| **Nitpick** | Preference. Does not block |

Zero defects **and** zero smells to pass.

## What to look for, in order of how much it costs to miss

### 1. Arithmetic, the defect class that reaches patients

- **Every `as` cast.** Is the range provably safe? Is the rounding intended
  and stated? An `#[allow]` on a cast lint is a defect until justified at the
  site.
- **Every LUT and geometry formula against the cited PS3.3 section**, not
  against the comment above it. **The comment was generated by the same
  process as the code and is not independent evidence.**
- Boundary comparisons. VOI is `<=` at the low end and `>` at the high end.
  Symmetric operators are a defect.
- `LINEAR` uses `c - 0.5` and `w - 1`. `LINEAR_EXACT` uses neither. Code
  sharing one branch between them is a defect.
- Sign extension from `BitsStored - 1`, not from the container width.
- `PixelSpacing[0]` scales the **column** direction cosine.
- Slice spacing derived from projected IPP, never from a tag.

### 2. Would this test fail if the code were wrong?

**Mutate one constant, re-run, confirm red, revert.** Do this rather than
reading the test and forming an opinion. A test that passes both ways is a
defect, not a nitpick, because it will be counted as coverage forever.

Also: does the fixture's expected value cite a DICOM section, or was it copied
from the implementation's output? The second is a defect under HLD 27.2 R2.

### 3. Claims in prose

Every factual sentence in a plan, a review, an AS_BUILT entry or a doc comment
is checkable. **Execute the claim before accepting it.** Prose asserting what a
guard does is worth nothing next to the guard's observed output.

This is the highest-volume defect class in a documentation-heavy workflow, and
it compounds: a remediation that corrects one sentence and adds three
explaining it ships three new claims for the next pass to falsify. Prefer
deleting a wrong sentence to explaining it.

### 4. Things that exist and that nothing executes

A guard, a test, an assertion or a branch that is present, looks authoritative,
and is never reached. **This is the defect class that survives a green suite,**
because a suite cannot report on what it does not run.

Check by removing the thing the guard protects and watching the guard fail. If
it does not go red, it was never a guard.

### 5. Boundary and tier

- `wasm-bindgen` outside `ocelli-wasm`.
- Pixels crossing the boundary.
- A view over wasm memory built outside `packages/core/src/bulk.ts`.
- Allocation in the render loop.
- A tier path with no declared answer on one of the three tiers, or an answer
  that silently produces a *different result* rather than marking the feature
  unavailable. **Three tiers**: A (WebGPU), B (WebGL2), C (CPU, D-07).
- A CPU path that reimplements arithmetic `ocelli-pixel` already owns. §18
  requires the LUT chain to exist exactly once, and a second copy behind a
  tier check is the same defect as a second copy anywhere else, except harder
  to find because it only runs on hardware nobody develops on.
- More than one `queue.submit()` per frame.

### 6. Structure

Against `AGENTS.md`: a new trait, generic or `Box<dyn>` with one implementer,
outside the two declared extension points. A wrapper that only forwards.

## Two habits that end the loop faster

- **Execute every factual claim before writing it down.**
- **When re-applying an edit, assert the ABSENCE OF THE NEW TEXT, not the
  presence of its anchor.** An anchor survives its own insertion, so
  `count(anchor) == 1` passes on an already-edited file and the block lands
  twice. No formatter catches a duplicated comment.

## Output

Write `.claude/reviews/F-XXX-<aspect>-pass-N.md`:

```markdown
# F-XXX review, pass N

**Reviewed**: {diff range or working tree}
**Result**: {N defects, N smells, N nitpicks}

## Defects
### D1, {title}
**Where**: file:line
**What**: {the wrong behaviour}
**Why it is wrong**: {cite the HLD section or DICOM section}
**Evidence**: {the command run and its output, or the mutation tried}

## Smells
## Nitpicks
## Verified clean
{What was checked and found correct. Says what the pass covered, so a later
reader can tell a clean pass from a shallow one.}
```

The `## Verified clean` section is not padding. Without it a clean pass and a
pass that looked at nothing produce identical reports.
