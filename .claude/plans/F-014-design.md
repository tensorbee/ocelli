## What the specification does not cover

1. Section 11 requires permanence but does not define a capture record, its
   required provenance, or how a record is linked to a generator case,
   manifest row, independent expectation and regression boundary.
2. The HLD does not define how a report derived from a clinical file is reduced
   to a synthetic recipe without retaining patient data. Repository policy
   supplies the answer: no input file, identifier, metadata dump, screenshot,
   pixel excerpt or digest of the input enters a prompt or tracked artefact.
3. The HLD does not define which mutation proves a captured case is active.
   `CURRENT_SPRINT.md` requires the named regression to be observed red for the
   declared reason and rejects a digest-only check.
4. Section 11's CI mechanism remains replaced by D-04. The standing capture
   record can be checked in the CI floor, while its full renderer regression
   runs locally through the sprint and oracle gates.
5. F-012 is still pending. Its approved design owns the binding candidate
   comparison and coverage result that F-014 must cite. F-014 implementation
   does not start until that dependency lands.

## Approach

Add one declarative capture record and one checker rather than another prose
checklist. A reader can answer what a captured quirk proves from the record,
and the checker can refuse a record whose evidence has parted company from the
tree.

1. Add `corpus/quirks.json` as the single tracked registry. Each entry has a
   stable quirk ID, a non-sensitive symptom description, one generator recipe,
   one or more exact manifest paths, an independently written expected-value
   fixture, a normative authority, the production regression command, the
   controlled mutation and the failure signature observed from it. The record
   never contains any field input or any value copied from one.
2. Restrict expectation provenance to structured authority kinds. The initial
   kinds are `dicom-standard` with part, section and edition, and
   `hand-calculation` with named inputs and literal steps. Neither Ocelli nor
   cornerstone3D is a permitted expectation authority. The oracle remains the
   golden-image comparison, not the source of a hand-computed answer.
3. Add `scripts/quirk_check.py`. It validates the schema, refuses missing
   authority or mutation evidence, requires every recipe to name a callable
   case in `scripts/corpus_synth.py`, and requires every declared generated
   path to have one matching `corpus/manifest.tsv` row sourced from that
   generator. It also refuses a tracked generated DICOM path. The existing
   staged-content guard remains the byte-level patient-data and DICOM refusal.
4. Put the checker and its negative fixtures in the CI floor. This checks that
   the evidence graph is complete without a corpus or GPU. Do not run commands
   taken from JSON. The checker accepts only named regression and mutation
   kinds that its code understands.
5. Demonstrate the full path with one deliberately small synthetic stored-value
   case. Its raw words and decoded signed values are literal fixture data
   derived from DICOM PS3.3 C.7.6.3.1.1 and C.7.6.3.1.4. The case is generated
   below `corpus/data`, represented by a manifest row, and selected by the
   candidate gate delivered by F-012.
6. Add a controlled mutation that sign-extends from `BitsAllocated - 1`
   instead of `BitsStored - 1`. The named regression must fail on the worked
   case with the stored-value boundary in its output, then pass with the
   mutation absent. Record that command and failure signature in the capture
   record. A digest mismatch does not satisfy this step.
7. Document the intake path. The operator records only a non-sensitive defect
   shape, reconstructs it with synthetic constants, cites the independent
   authority, adds the generator and manifest link, adds the production
   regression, proves the mutation red, and then runs the corpus and oracle
   gates. A report that cannot be reduced without retaining patient data is
   not captured in this repository.

No tolerance changes are part of this story.

## Boundary and tier

- wasm-bindgen: not touched
- Pixels across the boundary: no. Generated bytes enter through the existing corpus and candidate-render paths
- Render-loop allocation: none. This story supplies test data, registry validation and a test-only mutation
- unsafe: none
- Tier A (WebGPU): full through F-012's candidate comparison after that dependency lands
- Tier B (WebGL2): full through the same renderer-output contract, with the resolved tier recorded by the candidate
- Tier C (CPU): full through the same renderer-output contract, with the resolved tier recorded by the candidate

The registry checker is tier-independent. A capture whose production boundary
is unavailable on the resolved tier records and tests that explicit
unavailability rather than silently selecting another answer.

## Tests

| Category | What it proves | Where |
|----------|----------------|-------|
| unit | Missing authority, missing recipe, an Ocelli-derived expectation, an absent manifest row, an unknown regression kind and absent mutation evidence are each refused by name | `scripts/tests/test_quirk_check.py` |
| fixture | The worked raw words decode to literal signed values derived from DICOM PS3.3 C.7.6.3.1.1 and C.7.6.3.1.4, independently of the candidate implementation | `scripts/tests/test_corpus_synth.py` |
| conformance | The generated case declares the pixel module and transfer syntax that its record cites, and its manifest digest matches | `scripts/tests/test_corpus_synth.py` and `bin/ocelli.sh gate corpus` |
| golden | F-012's binding candidate comparison selects the captured manifest path and judges it against the fixed tolerance policy | `bin/ocelli.sh gate oracle` |
| browser | The worked case reaches decode, presentation and readback through the reference and candidate render paths | `tools/oracle/run.mjs` and F-012's candidate runner |
| mutation | Sign extension from the wrong bit makes the worked regression red at the stored-value boundary, while the unmutated case is green | `tools/oracle/src/mutations.rs` and the F-012 candidate gate |

The fixture values are written from the cited DICOM sections before the
candidate path is touched. The mutation proves that the case drives the
production boundary rather than merely matching its manifest digest.
