# F-193, overlay planes and display shutters

**Status**: approved
**Epic ref**: E38.3
**Sprint**: S42
**Estimate**: 3w

## Normative source, transcribed

HLD section 18 stage 3 is the presentation LUT. A display shutter is not that stage. The HLD does not specify overlay group `60xx` or shutter shape. HLD section 19's render list names `SegOverlay` for segmentation, which is `ocelli-seg` and is not an image overlay plane. This story does not change that pass.

`docs/hld/B-parity-surface.md` has no overlay-plane or display-shutter row. This story covers none.

## What the specification does not cover

The story names DICOM PS3.3 C.9.2, C.7.6.11 and C.7.6.15. The current standard text says:

C.9.2. An overlay plane has rows `(60xx,0010)`, columns `(60xx,0011)`, type `(60xx,0040)` of `G` or `R`, origin `(60xx,0050)` as row and column with image pixel `1\1` at the upper left, bits allocated `(60xx,0100)`, bit position `(60xx,0102)`, and overlay data `(60xx,3000)`. Origin values below 1 place the overlay above or to the left of the image. `0\0` means one row above and one column to the left.

C.7.6.11. A display shutter is a geometric mask. Coordinates are 1-based from the upper left. Shutter Shape `(0018,1600)` may list rectangular, circular and polygonal shapes together. Rectangular edges are `(0018,1602)`, `(0018,1604)`, `(0018,1606)` and `(0018,1608)`. A polygon is closed from the last vertex to the first and its edges do not otherwise intersect. The neutral colour is Shutter Presentation Value `(0018,1622)` when present. When that attribute is absent or empty, the neutral colour is undefined and this story reports it absent rather than inventing black.

C.7.6.15. A bitmap shutter references one overlay group `(0018,1623)`. That overlay has type `G`, one bit allocated, bit position 0, origin `1\1`, and the same rows and columns as the image. Overlay data value 1 means the shutter applies. That overlay is not also shown as a graphic overlay.

This story returns the planes and the shutter description. It does not composite them in a shader. The page draws the synthetic result as text and as a small mask preview generated by the helper from the returned bits. The preview uses the shutter presentation value when it is present. When it is absent, the preview shows the mask and the sentence that the neutral value is absent.

## Problem and reproducer

A synthetic 4 by 4 monochrome object carries overlay group `6000` with a single bit set at overlay coordinate `(1,1)`, origin `1\1`, and a rectangular shutter whose edges exclude column 1. Expected: one overlay plane, one rectangular shutter, image pixel `(1,1)` inside the overlay and outside the shutter. Current behaviour: the attributes are ordinary metadata if someone asks, and nothing validates the module or applies the origin.

## Scope, API and compatibility

In scope:

- `crates/ocelli-dicom/src/overlay.rs`.
- Walk even overlay groups from `0x6000` through `0x601E`. A missing rows attribute ends the search for that group. A later group may still exist. DICOM allows sparse groups, so a gap does not stop the walk.
- Read 1-bit overlay data packed into bytes, low bit first in each byte, as PS3.5 overlay encoding requires. 16-bit allocated overlays are accepted only when bit position selects one bit. Any other allocated count is an error.
- Origin is applied when testing a pixel. A bit that lands outside the image is retained on the plane and reported outside. It is not clipped away silently.
- Shutters from C.7.6.11 and C.7.6.15. Bitmap shutter removes that overlay group from the graphic list and keeps it on the shutter.
- `contains(row, column)` for a shutter uses 1-based image coordinates. Row and column below 1 are outside.
- Page panel and `POST /overlay` on the F-191 helper.
- Synthetic 4 by 4 fixture button.

Out of scope:

- Overlay activation module C.11.7 beyond the bitmap-shutter rule that the referenced overlay is not activated.
- Multi-frame overlay per-frame functional groups. A per-frame overlay that cannot be read from the top-level groups is `FrameOverlayUnsupported` for that frame, not a blank success.
- Drawing the overlay in `ocelli-render`. F-200 is the viewer manipulation story that can composite later. This panel is the S42 display.
- Changing segmentation overlays.

```rust
    Roi,
}

pub struct OverlayPlane { /* rows, columns, type, origin, bits */ }

pub enum ShutterShape {
    Rectangular { left: i32, right: i32, upper: i32, lower: i32 },
    Circular { center_row: f64, center_column: f64, radius: f64 },
    Polygonal { vertices: Vec<(i32, i32)> },
    Bitmap { group: u16 },

pub fn read_overlays(parsed: &ParsedDicom, frame: u32) -> Result<OverlaySet, OverlayError>;
```

`OverlayPlane::bit(row, column)` uses 1-based overlay coordinates after origin shift into image coordinates. `Shutter::hides(row, column)` is true when the pixel is outside the geometric opening, or when the bitmap bit is 1.

Polygon self-intersection is a refusal. An open edge list is closed by the rule above before that test.

The origin shift is integer addition of the 1-based origin. No millimetre conversion.

## State transitions and invariants

Stateless. Reading twice returns equal planes. A refusal does not return a partial plane list.

Invariant. A bitmap shutter group appears in exactly one place. A test that leaves it in both the graphic list and the shutter fails.

Invariant. Overlay bits are not passed through `LutChain`.

## Ownership, commit and recovery

Same as F-191. The mask preview is a response of bit counts and a few coordinates, not a pixel buffer of the source image. The synthetic preview may return 16 mask bits because the fixture is 4 by 4 and contains no patient pixels.

## Approach

Implement bit unpacking once in `overlay.rs`. Use `MetadataSet` for the top-level attributes. Do not decode Pixel Data.

Rectangle tests are inclusive on the edges that bound the opening. A pixel with column less than the left edge or greater than the right edge is hidden. The same rule applies to rows. The standard's edge attributes are the opening edges.

Circle uses the centre and radius attributes `(0018,1610)`, `(0018,1612)` and `(0018,1614)`. A pixel centre at the 1-based coordinate is inside when its distance to the centre is less than or equal to the radius. The comparison is on `f64` distance squared, with equality on the exact radius. No new epsilon.

Rejected. A shader shutter in this story. Reusing `ocelli-seg` contours for overlay bits.
