## Defects

### D1, The cache LLD says F-034 counts CacheEvents

**Where**: `docs/lld/cache.md:158`
**What**: The decoded-tier section says F-034 counts evictions from the three `CacheEvent` variants. `TierCounters::record` takes an `Admission` and never reads a `CacheEvent`. The F-034 section of the same file says the counters fold `Admission`. The file disagrees with itself, and the code matches the later sentence.
**Why it is wrong**: A claim in prose that is false is a defect. The plan counts `admission.evicted` and ignores `displaced`. `CacheEvent` is a separate encoding produced by `ImageCache::insert`. A reader who follows line 158 would count the wrong value, and would miss `set_budget`, which returns an `Admission` and does not build a `CacheEvent`.
**Evidence**: `crates/ocelli-cache/src/telemetry.rs:63` is `record(&Admission)`. The body at lines 64 to 70 increments `evicted` from `admission.evicted` and `refused` from `admission.refused`. A search of `telemetry.rs` for `CacheEvent` returns no matches. `docs/lld/cache.md:194` says `TierCounters` folds `Admission`.

## Nitpicks

### N1, `evicted_bytes` re-reads `Budgeted::bytes`

**Where**: `crates/ocelli-cache/src/telemetry.rs:66`
**What**: `record` adds `value.bytes()` after `Lru` has dropped `Entry.bytes`, the size stored at admission. `Admission` still returns only the value. The field comment says this equals the admitted size when `bytes` does not change. The property test uses `Block`, which never changes, so the reported sum cannot disagree with the drop in `used`.
**Judgment**: Not a defect and not a smell. The plan's `record` signature only receives `Admission`, so the stored size is not available. `DecodedFrame::bytes` is the sample length and has no mutator. The comment states the limit instead of claiming an unconditional equality. The gap pass 1 left is still there, and it is still a nitpick.

### N2, Encoded's wire code is not pinned

**Where**: `crates/ocelli-cache/src/telemetry.rs:182` and `crates/ocelli-cache/tests/telemetry.rs:77`
**What**: `tier_code` maps Encoded to 0, Decoded to 1 and Gpu to 2. The pressure fixture asserts Gpu as 2. The budget fixture asserts Decoded as 1. Neither encodes Encoded, so changing that arm alone leaves the suite green. The code is 0 today. This is a missing pin, not a wrong code.
