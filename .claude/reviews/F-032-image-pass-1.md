## Defects

### D1, the wire kind numbers 1, 2 and 3 are pinned by no test

**Where**: `crates/ocelli-cache/src/image.rs:134` to `crates/ocelli-cache/src/image.rs:138`, and `crates/ocelli-cache/tests/image_cache.rs:168` to `crates/ocelli-cache/tests/image_cache.rs:174`
**What**: `KIND_EVICTED` is 1, `KIND_DISPLACED` is 2 and `KIND_REFUSED` is 3. The only test that touches the numbers asserts that the three encoded kinds are pairwise distinct. The layout test asserts the raw kind word equals `event.kind`, which compares the encoding to itself. No test asserts that an evicted event encodes kind 1.
**Why it is wrong**: HLD section 17.3 makes `kind` the word the JavaScript reader switches on, and decision B1 in the approved plan keeps three bare constants until F-103 decides on a registry. With no registry, the test is the only thing holding the numbers still. Renumbering is a silent wire break that F-101 would inherit. The microscope rule for this class is direct. A test that passes both ways is a defect, because it will be counted as coverage forever.
**Evidence**: swapped the two constants so `KIND_EVICTED` was 2 and `KIND_DISPLACED` was 1, then ran `bin/ocelli.sh test ocelli-cache --test image_cache`. Result was 6 passed and exit 0. The mutation was reverted exactly and the file was read back to confirm the original values.

### D2, the randomised event accounting test the plan promises does not exist

**Where**: `.claude/plans/F-032-design.md:234`, the `property` row of the Tests table, against the whole of `crates/ocelli-cache/tests/image_cache.rs`
**What**: The plan requires a property over a randomised insert and get sequence, where the sum of the `Evicted`, `Displaced` and `Refused` byte counts equals the bytes the cache stopped holding. The new test file holds six deterministic tests and imports no property harness. The only randomised file in the crate, `crates/ocelli-cache/tests/invariants.rs`, drives `Lru<u8, Block>` and never constructs an `ImageCache`, a `DecodedFrame` or a `CacheEvent`, so the `Admission` to `CacheEvent` conversion in `ImageCache::insert` is exercised at varied sizes by nothing.
**Why it is wrong**: HLD section 20 keeps the budget in admitted bytes, and F-034 will count evictions from these events. The deterministic tests use 100-byte frames on both sides of each assertion, so the byte each variant reports is the least varied input in the suite. The plan made the randomised row the check that the three variants together account for what left, and that check was not delivered.
**Evidence**: `bin/ocelli.sh test ocelli-cache` ran the new file as 6 tests, all named and none randomised. Reading `crates/ocelli-cache/tests/invariants.rs:16` shows the property harness bound to `Lru` alone. No command output shows an `ImageCache` property, because there is none to run.

### D3, the plan says one insert allocates nothing and holds at most three events, and neither holds

**Where**: `.claude/plans/F-032-design.md:215` to `.claude/plans/F-032-design.md:216`, against `crates/ocelli-cache/src/image.rs:194` to `crates/ocelli-cache/src/image.rs:196`
**What**: The Boundary and tier block says `CacheEvents` is a small fixed-capacity value, three variants at most per insert, so emitting one allocates nothing. `CacheEvents` wraps a `Vec<CacheEvent>`, which allocates on the heap as it grows, and one insert can evict without bound. The code doc comment at `crates/ocelli-cache/src/image.rs:192` already states the truth, that building the value allocates as `Lru::insert` already does. The plan sentence and the code disagree, and the plan records no deviation for it, where it says none is expected.
**Why it is wrong**: A claim in prose that is false is a defect under the microscope severity table. The code behaviour is the right one, because HLD section 20 allows `insert` to allocate and forbids allocation in the render loop, and `insert` is a decode path call. A fixed three-slot value would have to drop evictions, which is the outcome deviation D-24 exists to keep visible. The fix is to delete the false sentence from the plan, not to cap the event list.
**Evidence**: a temporary probe test file was created, run and then deleted. One probe filled a 1000-byte cache with ten 100-byte frames and inserted one 1000-byte frame. The returned `CacheEvents` held 10 events, all `Evicted`, and the probe passed. `git status --porcelain` after deletion showed only the six F-032 paths from the scope line above.

## Smells

### S1, the read side of `ImageCache` and the `DecodedFrame` accessors are executed by no committed test

**Where**: `crates/ocelli-cache/src/image.rs:78` to `crates/ocelli-cache/src/image.rs:91`, `crates/ocelli-cache/src/image.rs:211` to `crates/ocelli-cache/src/image.rs:214`, and `crates/ocelli-cache/src/image.rs:258` to `crates/ocelli-cache/src/image.rs:271`
**What**: The committed tests call `ImageCache::insert` and nothing else on the cache. `get`, `remove` and `pressure` have no call site in the workspace outside their definitions, `CacheEvents::len` is never called, and `description`, `plane` and `samples` are never read. The combined insert that both displaces and evicts in one call, which is the one ordering claim `CacheEvents::events` documents, is also untested. Each wrapper is one line over `Lru`, whose own behaviour is well tested, so the gap is in the facade and not in the budget mechanics.
**Why it matters**: This is the never-reached class that survives a green suite, because the suite cannot report on what it does not run. A swapped `get` and `remove`, or a displaced event pushed after the evictions, would ship green today. The behaviour is correct now, which is why this is a smell and not a defect.
**Evidence**: searched the workspace for `ImageCache` uses. Outside the definitions, the only hits are the import and the two `ImageCache::new` calls in the insert tests. The same temporary probe then exercised the missing paths and passed on all four probes, covering combined displaced-then-evicted order, exact-budget admission, zero-budget refusal of a zero-byte frame, and `pressure` falling to zero after `remove`. Correct behaviour with no committed net is the finding.

## Nitpicks

1. `crates/ocelli-cache/src/lib.rs:26` re-exports seven names from `image` and omits `KIND_EVICTED`, `KIND_DISPLACED` and `KIND_REFUSED`. The constants are public through `ocelli_cache::image`, so this breaks nothing, and the root is where a reader looks first for the kind words that `RingEvent::kind` documents.
2. `crates/ocelli-cache/tests/image_cache.rs:86` to `crates/ocelli-cache/tests/image_cache.rs:102` asserts raw words at offsets 0, 4 and 8 and then reads the payload through the typed field. The layout is pinned in fact, because size 48 with `seq` ending at 16 leaves the payload at 16, and a probe asserted the raw slice at 16 equals the payload and passed. One direct assertion on the raw slice would state what the JavaScript reader depends on, instead of leaving it to be derived.
3. The header at `crates/ocelli-cache/tests/image_cache.rs:3` to `crates/ocelli-cache/tests/image_cache.rs:6` cites the plan for the 524,288-byte frame. The arithmetic is shown and hand-checkable, and `crates/ocelli-cache/tests/budget.rs` cites DICOM PS3.3 C.7.6.3.1 for the same product. Citing the section here too would keep the fixture provenance in the file that asserts it.

## Verified clean

**Casts and arithmetic.** There is no `as` cast in `crates/ocelli-cache/src/image.rs` outside doc comments, confirmed by search, and no cast lint allowance in either new file. The one numeric conversion, `usize` to `u64` for the payload byte count at `crates/ocelli-cache/src/image.rs:179`, uses `try_from` with saturation to `u64::MAX`. On wasm32 and on 64-bit native targets the conversion cannot fail, so the saturation arm is unreachable and harmless. Payload writes are four fixed slices of 8, 4, 4 and 8 bytes into a zeroed 32-byte array, which leaves the last eight bytes zero, and the round-trip test reads each field back little-endian. `DecodedFrame::bytes` at `crates/ocelli-cache/src/image.rs:94` returns the buffer length and performs no rows by columns arithmetic at all, which is the design intent. No LUT, VOI or geometry formula appears in this diff. `ImagePlane` and `StoredPixelDescription` are carried as opaque validated values from `ocelli-pixel`, and no `PixelSpacing` scaling is computed here. Budget admission inclusivity, where an entry of exactly the budget is admitted, is inherited from `Lru::would_admit` and was confirmed through `ImageCache` by probe.

**Tests would fail if the code were wrong.** Three mutations were applied, run and reverted exactly, with the file read back after each revert. Collapsing `Displaced` into `Evicted` inside `ImageCache::insert` made `displaced_and_refused_are_not_evicted` fail with exit 101, left `Evicted` against right `Displaced`. Swapping the instance and frame payload writes made `eviction_payload_round_trips_little_endian` fail with exit 101, left 2 against right 3. Returning zero from `DecodedFrame::bytes` made `frame_bytes_is_the_allocated_buffer` fail with exit 101, left 0 against right 524288. The kind-number mutation is the single exception and is defect D1. Fixture values are hand-computed in the test comments, 512 by 512 by 2 equals 524,288, and the layout numbers come from HLD section 17.3, not from implementation output.

**Prose claims, executed.** The module claim that no ring is built and nothing reaches JavaScript holds. No ring file was added, and the scope diff adds no `ocelli-wasm` path. The claim that `bytes` follows the buffer when description and buffer disagree is the malformed pair in `frame_bytes_is_the_allocated_buffer`, which passes. The claim that a displaced value comes before any eviction was executed by probe, budget 250 with two 100-byte frames live and a 200-byte replacement, and returned displaced first and evicted second in that order. The claim that `remove` emits no event holds by construction, because `remove` returns `Option<DecodedFrame>` and has no event type to emit, and the probe confirmed `pressure` accounting around it. The claim that reading is a use and `pressure` is not a use holds by delegation to `Lru::get` and `Lru::pressure`, whose own tests cover tick behaviour. The one false prose claim found is defect D3.

**Dead and unreached code.** Each `Admission` field maps to exactly one `CacheEvent` variant, and each variant is constructed in the tests, evicted and displaced and refused all observed. Each arm of the kind mapping in `CacheEvent::parts` is encoded by the mixed test that walks all three variants. `FrameKey::new`, `SeriesId`, `CacheEvents::events` and `is_empty` are all executed. The unexecuted surface is smell S1 and nothing else. No branch in `encode` exists beyond the three-arm match, and the reserved payload tail is asserted zero by the round-trip test.

**Boundary and tier.** Search for `unsafe` and for `wasm-bindgen` across both new and modified cache files returned no hits. The event payload carries series, instance, frame and byte count only. No sample crosses in an event, which keeps decision D3. No view over wasm memory is built, and no ring exists to drain, so the per-frame drain and the single `queue.submit` rule have nothing to act on in this diff. Allocation happens on the insert path only, through the `Vec` in `CacheEvents` and the map in `Lru`, and `get` and `pressure` allocate nothing. That is the decode path, not the render loop. Tier A, tier B and tier C are not applicable in the sense the plan records. `ImageCache` always builds its `Lru` over `CacheTier::Decoded` and contains no tier conditional, so the cache behaves identically whatever renders. The crate keeps its `no_std` attribute with `extern crate alloc`, takes `Vec` from `alloc`, and its two new dependencies are `bytemuck` from the workspace and `ocelli-pixel` by path. `bytemuck` was already a dependency of `ocelli-render`, so this is its second consumer, as the plan records. `Cargo.lock` adds exactly those two edges to `ocelli-cache` and nothing else. The `BACKLOG.md` change is the single status word from pending to in-progress for F-032.

**Structure.** No new trait is declared. The diff implements the existing `Budgeted` trait for one new value type, which already has other implementers. No new generic parameter appears. `ImageCache` is concrete over `FrameKey` and `DecodedFrame`, and there is no `Box<dyn>`, no `Arc<dyn>` and no feature flag. `ImageCache` is not a forwarding wrapper under the `AGENTS.md` test, because it fixes the tier to decoded, fixes the key and value types, and translates `Admission` into reportable events, which removes choices a caller of raw `Lru` would otherwise face. The three one-line read methods forward inside a type that earns its place on the insert path.

**Suite and lints.** `bin/ocelli.sh test ocelli-cache` passed with exit 0 after all mutations were reverted, 21 unit tests, 4 budget tests, 6 image cache tests and 2 invariant tests, 33 in total. `bin/ocelli.sh clippy ocelli-cache` passed with exit 0. Exit codes were read from the commands directly, with no pipe in either invocation.
