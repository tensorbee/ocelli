## Defects
### D1, The single VOI write route is never executed
**Where**: [graph.rs](/Users/atulsharma/Documents/projects/tensorbee/ocelli/crates/ocelli-render/src/graph.rs:632)
**What**: No test and no production caller invokes `set_voi`. Its thirty-two byte uniform write, its VOI dirty marking, and its `PassHasNoUniform` guard can all change without any test changing. Every graph test sets the window only through `StackPass` at registration, so the window change path the approved design names has no driving test at all.
**Why it is wrong**: The approved design Approach section 6 makes `set_voi` the only route that sets VOI dirt, so a window change cannot update bytes without scheduling the frame that shows them. HLD section 18 requires the LUT chain to exist once in `ocelli-pixel` and the shader to read resolved parameters. The microscope rule is that a test which passes both ways is a defect because it will be counted as coverage forever. A guard nobody executes is the same defect class.
**Evidence**: A workspace search counts zero `set_voi` call sites in [graph.rs tests](/Users/atulsharma/Documents/projects/tensorbee/ocelli/crates/ocelli-render/tests/graph.rs) and in [graph_voi.rs tests](/Users/atulsharma/Documents/projects/tensorbee/ocelli/crates/ocelli-render/tests/graph_voi.rs) and two occurrences in the source file for the doc phrase and the definition. Deleting the `PassHasNoUniform` guard left `bin/ocelli.sh test ocelli-render` at exit 0 and left `bin/ocelli.sh gate gpu` at exit 0 with ALL GREEN. The mutation was reverted and the restored source matches the pre-mutation copy byte for byte.

## Smells
### S1, Recovery install does nothing in silence when the recovered value carries no graph resources
**Where**: [graph.rs](/Users/atulsharma/Documents/projects/tensorbee/ocelli/crates/ocelli-render/src/graph.rs:668)
**What**: `install_recovered` returns at once when `recovered.graph` is `None`. Layouts, pipelines, per-viewport slots, and dirt all stay as they were. A following tick can then bind objects the dead device owned, which is the failure the `Some` path now fixes.
**Why it is wrong**: HLD section 22 requires rebuild of the device and all resources. The doc comment on the method says it marks every viewport fully dirty because every GPU object the old device owned is gone, and it states no `None` exception. The sanctioned production flow always carries `Some` after `RenderGraph::new` registers its count, so the arm is latent today. A caller that installs a hand-built value or installs on a graph whose registration lived on another context gets silent stale state instead of an unavailable answer, and the next story to touch recovery will inherit that edge.
**Evidence**: Reading the body shows the early return before the compile call and before the slot clearing loop. Reading [gpu.rs](/Users/atulsharma/Documents/projects/tensorbee/ocelli/crates/ocelli-render/src/gpu.rs:238) shows registration is what makes the production value carry `Some`. No test drives the `None` arm.

### S2, The VOI write returns the wrong error variant at both edges of its lookup
**Where**: [graph.rs](/Users/atulsharma/Documents/projects/tensorbee/ocelli/crates/ocelli-render/src/graph.rs:638)
**What**: Chain validation runs first. The pass lookup then maps a missing entry to `is_stack` false, so an id this graph never issued returns `PassHasNoUniform`. A known stack viewport whose slot is still `None` after recovery and before `rebind` returns `UnknownViewport` even though the id was registered. A non-stack viewport with a sequence chain returns the `Voi` error rather than `PassHasNoUniform`.
**Why it is wrong**: [graph.rs](/Users/atulsharma/Documents/projects/tensorbee/ocelli/crates/ocelli-render/src/graph.rs:185) defines `UnknownViewport` as an id this graph never issued. Both returns contradict that definition, and the doc comment on `set_voi` lists only the `Voi` error so neither edge is documented. Every case returns an error today so no wrong frame renders, which keeps this a smell. A caller that matches on the variant to choose between reporting an unknown id, reporting a pass with no uniform, and driving recovery will take the wrong branch once that caller exists.
**Evidence**: Reading the order in the body from chain conversion through the stack check to the slot lookup. The defect above records why no test can catch the ordering today.
