tracker** and the source of truth for story status. The story rationale,
architecture and acceptance context live in `docs/hld/`.

Statuses: `pending`, `in-progress`, `done`, `archived`, `superseded`.

Updated by `/complete-feature` (single-row updates) and `/sync-status`
(consistency audit). The row table below is the record. There is no generated
summary block, and the Summary section names the command that prints each
figure instead.

F-IDs F-001 to F-190 retain their bootstrap import order. The `Epic ref` column
carries the original planning ID so the HLD parity checklist, whose `Covered
by` column cites E-IDs, still resolves. This tracked file is authoritative.

## Summary

**There is no summary table here any more, and its removal is the fix.** What
stood here described itself as regenerated by `scripts/gen_backlog_summary.py`
and asserted by `/verify`. That script has never existed in this repository and
no gate ever read the block, so it was a self-describing autogenerated table
that nothing generated and nothing checked, in the file this repository calls
the source of truth for story status. By the S03 sprint review's fourth pass
four of the five numbers in its Total row were wrong, and all four are named
here because the sixth pass counted them and named only three. The Total row
claimed **195 F-IDs, 0 done, 195 pending and 1043 engineer-weeks**, and the
commands below report every one of those four differently today. The fifth
cell, zero in progress, still holds.

**The M1 and Phase 1 figures are not Total-row numbers**, and this paragraph
used to list them after the colon as though they were. They came from the
milestone rows and from the counting-rule note under the table, which put M1 at
16 stories and 40 weeks and Phase 1 at 417 weeks across 123 stories. Of the
nineteen milestone rows only M1's was wrong, and of the per-phase figures only
Phase 1.5's 39 stories and 352 weeks still held.

A number in this file has to have a command beside it. These are the commands.

| Figure | Command |
|--------|---------|
| Total F-IDs, how many are `done`, declared import defects | `python3 scripts/backlog_check.py` |
| F-IDs carrying a sprint, and whether every sprint and estimate agrees with the allocation | `python3 scripts/gen_sprint_plan.py --check` |
| Stories and engineer-weeks per phase and per milestone, and the totals | the one-liner below |

```bash
python3 -c "
import json, collections
s = json.load(open('docs/sprints/allocation.json'))['stories']
n = collections.Counter()
w = collections.Counter()
for x in s:
    k = (x['phase'], x['milestone'] or '-')
    n[k] += 1
    w[k] += x['weeks']
for k in sorted(n): print(k[0], k[1], n[k], 'stories', w[k], 'weeks')
print('TOTAL', sum(n.values()), 'stories', sum(w.values()), 'weeks')
print('sprints', len({x['sprint'] for x in s if x['sprint']}),
      'milestones', len({x['milestone'] for x in s if x['milestone']}))
"
```

_Counting rule. Each F-ID is counted exactly once, in the milestone it
occupies. Phase 2 and Phase 3 rows carry no milestone and no sprint, they are
tracked but unscheduled. F-202 to F-205 are Phase 1 and are now allocated to the M21
showcase completion waves. Only Phase 2 and Phase 3 rows remain unscheduled._

_HLD section 38 states Phase 1 grows from 382 to 397 engineer-weeks to carry
the five Part III hooks, which are F-008 (E1.8), F-015 (E2.7), F-036 (E5.6),
F-058 (E8.8) and F-094 (E15.1). Those five are inside the allocation the
one-liner sums, and `python3 scripts/backlog_check.py` asserts they are
scheduled in Phase 1. **The IMPORTED Phase 1 rows still total exactly 397
engineer-weeks, and Phase 1 as allocated is larger**, because every `F-X` story
added since the import lands in Phase 1. Splitting the two is a one-line change
to the command above, adding `x.get('added')` to the key, and the split is not
transcribed here for the reason this whole section exists. The HLD's figure and
the allocation's figure are both correct and they are answers to different
questions._
