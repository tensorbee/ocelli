# Key object and secondary capture

**F-IDs that contributed:** F-196, F-215
**Last updated:** 2026-11-08

`writeKeyObject` and `readKeyObject` live in `packages/core`. dcmjs 0.52.2 writes one Key Object Selection document. The SOP class is `1.2.840.10008.5.1.4.1.1.88.59`. The template identifier is 2010. PS3.16 TID 2010 row 1 is the coded title `(113000, DCM, "Of Interest")`. The caller title is row 7, `(113012, DCM, "Key Object Description")`. Row 10 was one COMPOSITE reference until F-215, which writes a reference to an image storage class as an IMAGE item, row 8, a waveform storage class as a WAVEFORM item, row 9, and any other class as a COMPOSITE item, row 10. The image classes follow one rule: every class of PS3.4 Table B.5-1 whose IOD Module Table in PS3.3 includes the Image Pixel Module, C.7.6.3, or its floating point form, C.7.6.24, and the retired image storage classes of PS3.6 Annex A. Each entry in `tid2010.ts` names the IOD section it was checked against, in the 2026d edition. The waveform classes are those whose IOD includes the Waveform Module, C.10.9. A class added to the standard later is COMPOSITE until the list is extended. The reader returns that title and the referenced SOP class and instance. A TID 1500 document returns nothing. Changing only the template identifier to 1500 returns nothing. An empty title, a title of only spaces, or an empty UID returns nothing. Study, series and the document instance must be synthetic `2.25` values. The referenced instance is any well-formed DICOM UID. There is no patient module and no Rust twin.

`writeSecondaryCapture` and `readSecondaryCapture` write one 8-bit `MONOCHROME2` Secondary Capture image. The SOP class is `1.2.840.10008.5.1.4.1.1.7`. PS3.3 C.7.6.3 stores the caller bytes when their length is columns times rows. Columns and rows are at most 65535. An odd count is padded to an even length on write, and the reader returns the caller bytes without that pad. C.8.6.2 conversion type is `WSD`. The file has no window and no patient module. A short buffer returns nothing. The same inputs produce the same bytes.

F-215 adds `writeKeyObjects` and `readKeyObjects` for many references under one study. Each reference is an IMAGE, WAVEFORM or COMPOSITE item by the same rule, with an optional Referenced Frame Number, and must be named in the source's evidence, or nothing is written. Current Requested Procedure Evidence Sequence lists exactly the referenced instances, by series, as TID 2010 rows 8 to 10 require. The study UID is any well-formed UID, because it is the user's. The writer fills PS3.3 C.7.1.1 Patient Name and Patient ID, C.7.2.1 Study Instance UID, Study Date, Study Time and Accession Number from the source, writes Patient Birth Date, Patient Sex, Referring Physician's Name and Study ID empty, C.17.6.1 Series Number 1 and an empty Referenced Performed Procedure Step Sequence, C.7.5.1 Manufacturer `Ocelli`, and C.17.6.2 Instance Number 1, Content Date and Content Time. C.17.6.2 has no Predecessor Documents Sequence, so the folder viewer shows the newest Key Object Selection `Ocelli` wrote for a study. `writeTid1500Groups` fills the same modules for an SR, with C.17.2 Completion Flag `COMPLETE`, Verification Flag `UNVERIFIED`, an empty Performed Procedure Code Sequence, the evidence, and Predecessor Documents Sequence when the source names one, and TID 1001 observation context as a device observer.

`writeSecondaryCapture` writes the same PS3.10 Table 7.1-1 file meta as the other writers since F-215.

The F-196 writers are a TID 2010 content-tree round trip and an 8-bit secondary-capture pixel round trip. They are not complete Key Object Selection or Secondary Capture information objects. The key-object writer omits Current Requested Procedure Evidence Sequence, Content Date, Content Time, Instance Number and Series Number. The secondary-capture writer stores Instance Number 1 and omits Series Number. Both omit the Type 2 Patient Name and Patient ID. A conformant receiver may refuse the files.
