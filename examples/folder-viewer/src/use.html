Use the library

A guide to Ocelli as it exists in this repository today. Every name on this page is a real export, read from the source. Where a piece is not built yet, the page says so.

This folder viewer is not the wasm path. It is a native Rust process that reads a file you choose and draws each viewport's image through the same ocelli-pixel code. The browser path is a wasm core in a worker, described below. Nothing is published. There is no package on npm and no crate on crates.io. You build from this workspace and depend on it by path.

The window arithmetic lives once, in LutChain, and this page does not copy it. Where a formula matters, the page cites its DICOM section and points at the type that implements it.

1What Ocelli is

Ocelli is a medical imaging core for the browser, written in Rust and compiled to WebAssembly, with a TypeScript shell on top. It parses DICOM, decodes pixel data, runs the DICOM grey scale pipeline, derives patient geometry and renders through wgpu.

Phase 1 aims at feature parity with cornerstone3D 5.8.2. That project is the reference this one learns from and measures against, frame by frame. It is a debt to acknowledge. The API is new and deliberately not a drop-in replacement, which is decision D1.

The defect this design fears most is not a crash. It is a pixel that is quietly wrong. At the centre of a soft tissue CT window the VOI functions LINEAR and LINEAR_EXACT differ by 0.32 of 255. Nobody sees that in a screenshot. A pixel diff sees it at once, which is why the oracle exists and why every pixel function carries a fixture with hand computed values.

2Architecture

2.1Shell and core

The shell is TypeScript on the main thread. It owns the DOM, pointer and wheel events, the SVG annotation layer, tool interaction state, framework bindings and DICOMweb fetch.

The core is Rust in a worker. It owns parsing, decode, the LUT chain, geometry and rendering. Each worker holds one wasm instance and runs single threaded on stable Rust with no SharedArrayBuffer, which is decision D5.

2.2Three channels, and pixels never cross

Exactly three things cross the boundary between shell and core.

  1. Typed commands down. The shell packs commands such as Pan or SetWindow into one little endian buffer per frame.
  2. Raw bytes down. Encoded DICOM bytes are copied once into the core's linear memory through an allocate, write, commit sequence.
  3. Events up. The core writes events into a ring buffer. The shell drains it once per animation frame, never through a JavaScript callback per event, which is decision D4.

Decoded pixels never cross. They do not become JavaScript objects on their way to the GPU, which is decision D3 and the main architectural gain.

wasm-bindgen appears in exactly one crate, ocelli-wasm, which is decision D2. Every other crate is plain Rust, so a desktop or server target is a new entry point rather than a rewrite.

4Build from source

Everything runs natively. There is no container path, because a container has no GPU and no browser.

git config core.hooksPath .githooks
npm ci
bin/ocelli.sh gate --floor      # what CI runs: no GPU, no corpus

The inner loop works one crate at a time.

bin/ocelli.sh check ocelli-pixel     # cargo check -p ocelli-pixel --all-targets
bin/ocelli.sh test  ocelli-pixel     # cargo test -p ocelli-pixel
bin/ocelli.sh clippy ocelli-pixel

The wasm module is built by wasm-pack with --target web into crates/ocelli-wasm/pkg. The published module is @ocelli/wasm, staged from that build at pack time. bin/ocelli.sh gate wasm checks the decode split, builds both packs and then checks the recorded size budget.

bin/ocelli.sh wasm             # release wasm-pack build, no size check
bin/ocelli.sh gate wasm        # the build plus the decode split and the size budget
bin/ocelli.sh wasm --release
npm run build                  # each workspace's build script, tsc for the packages and vite for viewer-react
npm run dev                    # the folder viewer, the showcase, through bin/folder-viewer-dev.mjs

npm run dev builds @ocelli/core, selects the native folder viewer binary from cargo's compiler-artifact output and serves the page. The folder viewer is the showcase. The earlier React demo in examples/viewer-react is kept under npm run dev:boundary-demo, and its header reads core ready only after its worker has loaded the built module.

cargo run --release -p ocelli-folder-viewer   # prints one URL on 127.0.0.1

OCELLI_CACHE_MIB sets the folder viewer's cache. Beside it, a multiframe in which any frame's window comes from a per-frame functional group keeps every frame's inspect reply, up to 16 MiB across every file and outside that cache, so a frame's window list is asked for by file id after the file's bytes are dropped. GET /held reports that pool as kept.

Its region window loads the built packages/core/dist from the local process, which serves it under /lib/, so run npm run build -w @ocelli/core before starting the folder viewer. Without that build the region window reads unavailable and says so. Save marks and Load marks need the same build, and say so when it is missing.

The folder viewer keeps at most four request bodies at once, which is the coefficient of S_max in the resident set bound, and decodes on two threads, which is P in that bound. Every preview decodes there, one that carries the file's bytes included, and a decode permit ends with its decode, so a client that stops reading holds no permit. A request body is freed on the thread that allocated it. A decoded frame's sample buffer that leaves the cache is parked on a free list keyed by its exact byte length when cached bytes plus free bytes still fit the budget, and is freed otherwise. That list is inside the same 256 MiB budget, and the cache evicts to make room for a frame or for a free buffer. A decode takes a parked buffer of its length when there is one. When no free buffer has the length and a held file's frame does not fit beside the cached and free bytes, its decode takes the samples of the least recently used cached frame of that length only when no reply is still reading that frame, and allocates otherwise. A preview that carries the file's bytes never evicts and never takes a cached frame's samples, because its frame is not stored. At most two automatic series windows are computed at once, each holding up to 4 MiB outside OCELLI_CACHE_MIB while it runs, which is the bound's term P * 4 MiB, and a third waits for one of them to finish. Every grey byte the folder viewer holds counts against one fixed cap of 17,400,000 bytes, which is the bound's grey term P * N_max, with N_max the 3000 by 2900 frame the bound is stated for. A reply's grey counts from the moment its render is admitted until it is written. Each decode thread keeps at most one written grey to render into next, and that grey counts for as long as it is kept. A decode thread frees the grey it kept while any preview waits for room, and before it renders a grey less than half that size. A frame of more than 17,400,000 pixels, whose grey alone is over the cap, draws alone. Its grey is admitted only when no other grey is held, and while it is held no other grey is admitted, so grey bytes stay within the larger of the cap and that one frame. Its decode thread frees that grey after the write and does not keep it. Previews that wait for room are served in the order they first waited. A waiting preview is admitted only when every preview that waited before it has been admitted or has stopped waiting, and only when its grey fits. A preview that fits is admitted at once only when no preview waits, so it cannot pass one that waited first. No frame is refused for its size below the preview library's limit of 67,108,864 pixels. The resident bound is stated for frames within the design size. A frame over the design size can raise resident memory above that bound. Measured on the release binary with a synthetic 4740 by 5928 frame, the preview answered 200 with 28,098,720 grey bytes in 49.8 ms decoded and 25.5 ms cached. A smaller preview waited while that grey was held and was served 3.8 ms after it was released. Two such previews read together peaked at 28,098,720 grey bytes, one frame. With two clients previewing two such frames in a loop and reading every reply, twenty 512 by 512 previews sent among them all answered 200, the slowest in 42.0 ms. A preview whose grey does not fit waits for room for up to the 60 second write timeout, and answers 503 busy if none comes. A whole reply must be written within that timeout. GET /held reports grey, every grey byte under the cap, and grey_replies, the part held by replies not yet written. A page that abandons a request closes its connection, which releases its grey at once, within a millisecond when measured. A client that keeps a connection open without reading holds its grey until the write timeout, measured at 60.0 seconds. When such clients fill the cap, other previews wait up to the write timeout and then answer 503 busy. Measured with twenty such clients, five of six later previews answered 503 busy at 60.0 seconds and one was served at 58.95 seconds, when a stalled write timed out. While body-form previews wait, a file post can wait as long, because each of up to four waiting previews keeps its request body slot. Measured with four waiting, a file post waited 58.99 seconds. The folder viewer binary uses mimalloc as its global allocator. The pin is exact in the workspace manifest. No other crate does.

Two other gate profiles exist. bin/ocelli.sh gate --sprint runs every gate with no exception, and bin/ocelli.sh gate --all adds the GPU and corpus tiers. bin/ocelli.sh gate --list prints what each gate covers.

5JavaScript with @ocelli/core

Everything in this chapter is exported from packages/core/src/index.ts. The wasm functions it talks to are the wasm_bindgen exports in crates/ocelli-wasm/src/session.rs and canvas.rs, and the panic record exports install_panic_hook, panic_record_ptr and panic_record_len in lib.rs.

5.1Load the core in a worker

An embedding page serves this policy on every response, including the worker script:

Content-Security-Policy: default-src 'none'; script-src 'self' 'wasm-unsafe-eval'; worker-src 'self'; connect-src 'self'

The worker's own response controls its wasm compilation. Construct workers from URLs. A blob worker inherits its creator's policy. Add a remote DICOMweb origin to connect-src, and a CDN serving the wasm glue also needs its origin in script-src. This local folder viewer decodes in its process and uses page hashes without 'wasm-unsafe-eval'.

loadCore runs your initialiser once per realm. The module the initialiser loads is the @ocelli/wasm package. Built from source, bin/ocelli.sh wasm writes the same module to crates/ocelli-wasm/pkg. loadCore resolves true only after the initialiser returns, and coreAvailable() stays false until then. A thrown initialiser rejects with OcelliError code CoreLoadFailed. error.cause is the value the initialiser threw, and the flag stays false.

worker.jsimport init, * as wasm from "@ocelli/wasm";
import { coreAvailable, loadCore } from "@ocelli/core";

let memory = null;

try {
  await loadCore(async () => {
    const output = await init();     // wasm-bindgen's default export
    memory = output.memory;
    wasm.install_panic_hook();
  });
} catch (error) {
  // error.code is CoreLoadFailed. error.cause is the initialiser failure.
}
if (coreAvailable()) {
  const tier = await wasm.resolvedTier();   // "A", "B" or "C"
}

The session the worker drives is the module's exports plus its memory. This is the shape @ocelli/react calls OcelliSession.

const session = {
  memory,
  alloc: wasm.alloc,
  bulk_ticket: wasm.bulk_ticket,
  release_bulk: wasm.release_bulk,
  apply_commands: wasm.apply_commands,
  drain_events: wasm.drain_events,
  copy_state: wasm.copy_state,
  snapshot: wasm.snapshot,
  snapshot_error: wasm.snapshot_error,
  restore_snapshot: wasm.restore_snapshot,
};

5.2Viewport ids and commands

A ViewportId is a branded number. viewportId(1) makes one. The wasm session opens its stack viewport with identity 1, so that is the id the commands address. A slice index is a different number and is not a viewport id.

packCommands(viewportId, commands) writes one buffer for a list of PackedCommand values. The eleven kinds come from STACK_COMMANDS, and their ids from COMMAND_ID.

KindFields
Fitwidth, height, columns, rows
Panx, y

Rotateradians
FlipHorizontal, FlipVerticalenabled
SetWindowcentre, width, function of "linear", "linear_exact" or "sigmoid"

SetInvertinvert of "identity" or "inverse"
SetColormapcolormap of "grey" or "stops"

import {
  packCommands,
  sessionCommandSink,
  viewportId,
  writeCommands,
} from "@ocelli/core";

const id = viewportId(1);
const bytes = packCommands(id, [
  { kind: "SetWindow", centre: 40, width: 400, function: "linear_exact" },
  { kind: "Zoom", factor: 1.5 },
  { kind: "Scroll", step: 1 },
]);

// One buffer, one apply. Returns the core's answer, 0 is a refusal.
const applied = writeCommands({ memory }, sessionCommandSink(session), bytes);

packPointerFrame(viewportId, samples) turns a frame's worth of pointer samples into one buffer of Pan commands, so several samples are still one call.

sessionCommandSink adapts the numeric exports. Its alloc captures a lifetime ticket from bulk_ticket, and only that ticket may apply. Calling apply_commands by address on the adapter always refuses, because an address is not an authorisation.

5.3The event ring

The core's drain_events export returns the ring header and pending events already copied out of linear memory. drainRing reads that copy. It never takes a view over wasm memory, because a memory growth would detach it.

import { decodeNamedEvent, drainRing } from "@ocelli/core";

function onFrame() {
  const { events, dropped } = drainRing(session.drain_events());
  if (dropped !== 0) {
    // The shell is not draining fast enough. Report it, do not swallow it.
  }
  for (const raw of events) {
    const event = decodeNamedEvent(raw);
    if (event?.name === "frame.presented") {
      const { generation, drawnWidth, drawnHeight } = event.payload;
    }
  }
  requestAnimationFrame(onFrame);
}
requestAnimationFrame(onFrame);

The ring carries seven kinds today, in RING_EVENT_KIND: evicted, displaced, refused, pressure, budget changed, presented and released. decodeNamedEvent names them cache.evicted, cache.displaced, cache.refused, cache.pressure, cache.budgetChanged, frame.presented and cache.released. The session produces the cache kinds now: a commit that carries a content id, a budget change, a series release and a pressure crossing each land there. OCELLI_EVENTS lists the rest of the catalogue, including pointer, key, touch, tool and annotation names that the shell raises itself. CORNERSTONE_EVENT_MAP maps the cornerstone3D 5.8.2 event names onto these, and UNMAPPED_EVENTS names the ones with no counterpart.

5.4Reading state

copy_state() returns a copied 96 byte block. readViewportState reads it into plain numbers and returns null for any other length.

import { FLAG_INVERT, readViewportState } from "@ocelli/core";

const state = readViewportState(session.copy_state());
if (state !== null) {
  const { camera, voiCenter, voiWidth, sliceIndex, numSlices, flags } = state;
  const inverted = (flags & FLAG_INVERT) !== 0;
}

camera is HLD section 17.4's sixteen numbers. The other flag bits are FLAG_LOADING, FLAG_ERROR and FLAG_REFINING.

session.snapshot() returns copied JSON that parseSnapshot reads, and restore_snapshot(bytes) returns zero on success. That pair is how a shell rebuilds a viewport after a panic poisons an instance.

5.5Bytes into the core

A write into linear memory always follows one order. Allocate, build a view, write, let the view go, then commit with the ticket. writeFrame does exactly that and should not be refactored to keep the view.

import { sessionBulkSink, writeFrame } from "@ocelli/core";

// Throws "allocation refused" or "commit refused". Releases the ticket on failure.
writeFrame({ memory }, sessionBulkSink(session), sampleBytes, {
  viewport: 1,
  columns: 512,
  rows: 512,
  generation: 1,
});

For this call the session object needs the module's commit_frame export too. holdSessionBytes(wasm, bytes, previousTicket) copies a whole response into the session's one bulk slot and returns its ticket without parsing it. That slot is the only bulk allocation, so other writes refuse until release_bulk drops the ticket.

A commit that carries a content id with its stackIndex and stackEpoch is routed to the cache, and is cached if the session's frame budget admits it. A commit that carries a content id without both is refused with InvalidValue and nothing is committed. The budget is off by default, so setFrameBudget comes first. contentId hashes the SOP Instance UID, the transfer syntax UID and the encoded bytes into one identity in the core, over the same bulk slot, so there is no second hash in JavaScript.

import {
  contentId, sessionBulkSink, setFrameBudget, showResident, writeFrame, writeStack,
} from "@ocelli/core";

setFrameBudget(session, 256 * 1024 * 1024);
const epoch = writeStack(session, keys);
const content = contentId(session, sopInstanceUid, transferSyntaxUid, encoded);
writeFrame({ memory: session.memory }, sessionBulkSink(session), sampleBytes, {
  viewport: 1,
  columns: 512,
  rows: 512,
  generation: 0,
  stackIndex: 0,
  stackEpoch: epoch,
  content,
});

// Later, with no bytes crossing again. A wrong epoch returns false at any
// index. Under the current epoch a show answers only for the slice the
// viewport has selected, another index throws the coded CommitRefused,
// and at the selected index a miss or a stale entry returns false.
const slot = { index: 0, epoch, content, columns: 512, rows: 512 };
if (showResident(session, slot)) {
  // The frame is displayed. frameResident asks without showing, and at
  // the selected index a mismatched show returns false and removes the entry.
}

5.6DICOMweb

DicomwebClient is a bounded QIDO-RS, WADO-RS and WADO-URI GET client. Its constructor takes six options.

OptionType
studiesServiceUrlstring, the DICOMweb root that studies/... is appended to
wadoUriUrlstring, the WADO-URI endpoint
fetchtypeof fetch, so authentication stays yours
wasmWasmMemory, an object with memory
sinkDicomwebResponseSink, with alloc(len) and commit_dicomweb_response(ptr, len, kind)
cacheDicomwebCacheMode, optional, the fetch cache mode of every request. "no-cache" by default, which revalidates a stored response with the server before using it. "no-store", "reload" and "default" are accepted, and "default" opts in to the browser's heuristic freshness. Any other value, "force-cache" and "only-if-cached" among them, is refused at construction with DicomwebError code InvalidRequest

Each method validates its UIDs, fetches with the right Accept header, checks the content type and copies the body into memory once. It resolves to nothing. The body reaches you through the sink, with a kind object whose type is qido-json, wado-uri-part10, wado-rs-instances or wado-rs-frames.

import { DicomwebClient, DicomwebError, OcelliError, exportDecodedFrame } from "@ocelli/core";

const memory = new WebAssembly.Memory({ initial: 1, maximum: 1024 });
const wasm = { memory };
let held = null;

const client = new DicomwebClient({
  studiesServiceUrl: "https://pacs.example/dicom-web",
  wadoUriUrl: "https://pacs.example/wado",
  fetch: globalThis.fetch.bind(globalThis),
  wasm,
  sink: {
    alloc(len) {
      const ptr = memory.buffer.byteLength;
      memory.grow(Math.ceil(len / 65536));
      return ptr;
    },
    commit_dicomweb_response(ptr, len, kind) {
      held = { kind, bytes: new Uint8Array(exportDecodedFrame(wasm, ptr, len)) };
    },
  },
});

try {
  await client.searchStudies({ filters: [["PatientID", "X"]], limit: 10 });
  await client.searchSeries(studyUid);
  await client.searchInstances(studyUid, seriesUid);
  await client.retrieveInstance(studyUid, seriesUid, instanceUid);
  await client.retrieveFrames(studyUid, seriesUid, instanceUid, [1, 2], "application/octet-stream");
  await client.retrieveWadoUri(studyUid, seriesUid, instanceUid);
} catch (error) {
  if (error instanceof DicomwebError) {
    // error.code is InvalidRequest, Network, Aborted, HttpStatus or ContentType.
    // error.status is set for HttpStatus. No URL, header or body is kept.
  } else if (error instanceof OcelliError) {
    // Any other shell error. For an unknown option key, error.code is
    // UnknownOption and error.option names the key.
  }
}

That sink is the caller's, because the wasm session has no commit_dicomweb_response export yet. The Rust parser for these bodies exists as ocelli_dicom::DicomwebSource, shown in the Rust chapter, but no wasm export joins the two today.

5.7The element seam

Ocelli enables on a plain DOM element and dispatches events on it, as cornerstone3D does. That is what lets an application adopt it one viewport at a time.

import { disableElement, dispatchOnElement, enableElement } from "@ocelli/core";

const element = document.getElementById("view");
const seam = enableElement(element);           // null if already enabled

element.addEventListener("frame.presented", (event) => {
  const named = event.detail;                    // the OcelliNamedEvent
});

dispatchOnElement(element, decoded);             // a name outside OCELLI_EVENTS returns false
disableElement(element);

6React with @ocelli/react

OcelliViewport renders one host div, enables the element seam on it, and runs a pump that submits one command buffer and drains the ring once per animation frame. It does not draw pixels itself.

PropTypeMeaning
idstringUnique within a session. Written as data-ocelli-viewport.
viewportViewportIdThe viewport the pump addresses.
sessionOcelliSession | nullYours. Null is the absent state. There is no singleton.
classNamestringApplied to the host element.
onEvents(events, dropped) => voidThe named events of one drain.
onRefused(commands) => voidCommands the core refused.
 
import { viewportId } from "@ocelli/core";
import { OcelliViewport } from "@ocelli/react";
import type { OcelliSession } from "@ocelli/react";

export function Viewer({ session }: { session: OcelliSession | null }) {
  return (
    <OcelliViewport
      id="stack-1"
      viewport={viewportId(1)}
      session={session}
      onEvents={(events, dropped) => {
        for (const event of events) console.log(event.name);
      }}
    />
  );
}

The host carries data-ocelli-core="absent" while session is null and "ready" after.

To send commands, use the hook, which returns a pump, the latest state and drawing, which is the constant "unavailable" today.

import { useOcelliViewport } from "@ocelli/react";

const { pump, state, drawing } = useOcelliViewport({ viewport: viewportId(1), session });

pump?.enqueue({ kind: "ApplyPreset", preset: "lung" });   // sent on the next frame
const checkpoint = pump?.checkpoint();                       // snapshot and slice index
if (checkpoint) pump?.restore(checkpoint);

Outside React, createViewportPump(session, options) gives the same ViewportPump with enqueue, start, stop, flushNow, checkpoint and restore. examples/viewer-react/src/App.tsx is the boundary demo's mount.

7Rust, parse

ocelli_dicom::parse_part10(bytes: &[u8]) -> Result<ParsedDicom, ParseError> reads one Part 10 object from memory. File Meta Information is read first, the Transfer Syntax UID is resolved once, and there is no fallback parse.

use ocelli_dicom::{parse_part10, DispatchPath, ParseError};

fn open(bytes: &[u8]) -> Result<(), ParseError> {
    let parsed = parse_part10(bytes)?;
    let syntax = parsed.transfer_syntax();
    let uid: &str = syntax.uid();            // e.g. "1.2.840.10008.1.2.1"
    let encapsulated = syntax.dispatch_path() == DispatchPath::Encapsulated;
    let object = parsed.object();            // the dicom-rs DefaultDicomObject
    Ok(())
}

ParseError is #[non_exhaustive] and carries no input bytes, values, UIDs or paths. Its variants name the failure class, from TruncatedPart10 and MissingDicmPrefix to UnknownTransferSyntax and InvalidDataSet. A data set whose sequences nest deeper than MAX_SEQUENCE_DEPTH is refused as SequenceTooDeep, before any recursion. A caller can log a ParseError without logging patient data.

The data set projects into MetadataSet::from_object(parsed.object()), which MultiframeMetadata::new reads with per-frame, shared and top level precedence. open_frame(&parsed, frame) turns one zero based frame into the inputs of the LUT chain, covered in chapter 9. read_padding(&metadata, photometric, signed) reads the Pixel Padding Value range alone, without the window and flags that open_frame can refuse. cine_timing(&metadata) reads one object's cine timing alone, Frame Time Vector, Frame Time, Recommended Display Frame Rate and then Cine Rate, and does not read Preferred Playback Sequencing, so a bad value there never hides a good Frame Time.

Encapsulated Pixel Data reads per PS3.5 A.4. A zero-length Basic Offset Table Item is the table and every later Item a Fragment, at the top level and inside an Icon Image Sequence item. EncapsulatedFrameIndex::from_parsed(&parsed, frame_count) builds the frame index from the Extended Offset Table when it is present and from the Basic Offset Table otherwise. With an empty Basic table and more Fragments than frames, a JPEG, JPEG-LS, JPEG 2000 or HTJ2K frame is split at its codestream start and end markers, and a boundary the markers and the frame count do not prove is refused as FrameIndexError::BoundaryUnavailable. index.frame_fragments(frame) borrows that frame's Fragments in order.

use ocelli_dicom::{parse_part10, EncapsulatedFrameIndex, FrameIndexError};

let parsed = parse_part10(bytes)?;
let index = EncapsulatedFrameIndex::from_parsed(&parsed, frame_count)?;
let encoded: Vec<u8> = index.frame_fragments(0)?.concat();   // one frame's codestream

DICOMweb bodies parse through the same types. DicomwebSource implements SeriesSource::consume.

use ocelli_dicom::{DicomwebSource, SeriesSource, SourceBatch, SourceResponse, SourceResponseKind};

let response = SourceResponse::new(SourceResponseKind::QidoJson, body);
match DicomwebSource.consume(response)? {
    SourceBatch::Query(sets) => { /* Vec<MetadataSet> */ }
    SourceBatch::Instances(parsed) => { /* Vec<ParsedDicom> */ }
    SourceBatch::Frames(frames) => { /* frames.parts(), frames.part_bytes(i) */ }
}

A NIfTI-1.1 single file is read by parse_nifti into ParsedNifti, outside the DICOM path.

7.1Conformance report

ocelli_dicom::check_conformance(&parsed) -> ConformanceReport checks one parsed object against the rules it lists and nothing else. It never fails, changes nothing, and is never called by parse_part10 or open_frame, so a finding never stops a frame from opening. report.to_json() writes the JSON the folder viewer serves, and CONFORMANCE_SCOPE is its first field: "This report checks the rules it lists and nothing else. It is not a statement that the file conforms to DICOM."

use ocelli_dicom::{check_conformance, parse_part10, ConformanceRule};

let parsed = parse_part10(bytes)?;
let report = check_conformance(&parsed);
for finding in report.findings() {
    let rule: ConformanceRule = finding.rule;  // e.g. ConformanceRule::AsFormat
    let id = rule.id();                        // "AS-FORMAT"
    let section = rule.section();              // "PS3.5 6.2 Table 6.2-1"
}
let json: String = report.to_json();

The value rules run on every element, inside sequences too: the length, repertoire and format of every VR in PS3.5 Table 6.2-1, with lengths in characters where the table says characters, and the last value of an element allowed its one pad character by section 6.4. Value multiplicity is checked for the attributes the presence rules name, from a table transcribed from PS3.6 Table 6-1, and for no other attribute. Presence of Type 1, 1C, 2 and 2C attributes is checked for seven PS3.3 modules, Patient, General Study, General Series, General Image, Image Plane, Image Pixel and SOP Common, on four SOP classes: CR Image Storage, which has no Image Plane module, and CT, MR and PET Image Storage. Any other SOP class reports evaluated: false, and its value rules still run. Attributes inside a sequence are not checked for presence.

Conditions the data set alone cannot decide are named in modules.notChecked and never checked: Laterality, ContentDate, ContentTime, AnatomicalOrientationType, PixelAspectRatio, PixelPaddingRangeLimit, PixelDataProviderURL, PatientAlternativeCalendar, PatientSpeciesDescription, PatientSpeciesCodeSequence, PatientBreedDescription, PatientBreedCodeSequence, BreedRegistrationSequence, ResponsiblePerson, ResponsiblePersonRole, ResponsibleOrganization, DeidentificationMethod, DeidentificationMethodCodeSequence, EncryptedAttributesSequence, HL7StructuredDocumentReferenceSequence, QueryRetrieveView and ConversionSourceAttributesSequence. Enumerated Values and Defined Terms are not checked.

A finding carries its tag, its dictionary keyword, its sequence path, its rule, a 1-based value number where the rule is per value, and a measure: a length against its limit, a value count against its multiplicity, or a 0-based character index with a class. It never carries a value, part of one or a character code. The one value the report repeats is a SOP Class UID under the DICOM root 1.2.840.10008., because it decides the module scope.

In JavaScript, readConformanceReport(text) from @ocelli/core reads that JSON. It answers { ok: true, report }, or { ok: false, reason } with "json", "scope" when the scope sentence differs by any character, "rule" for a rule id outside CONFORMANCE_RULES, or "shape". Each finding's section is filled from CONFORMANCE_RULES, which is generated from the Rust rules, and never taken from the wire.

import { readConformanceReport } from "@ocelli/core";

const read = readConformanceReport(await response.text());
if (read.ok) {
  for (const finding of read.report.findings) console.log(finding.tag, finding.rule, finding.section);
}

The report is made in Rust, not in the browser. No wasm module links ocelli-dicom yet, so a browser build cannot produce one, and that waits for a wasm build that links the parser. This folder viewer answers POST /conformance with the report, by a held file's X-Ocelli-File id or with the file as the body, with the same error forms as POST /headers. The page reads it with readConformanceReport and shows it in Checks on the Headers sheet.

8Rust, decode

ocelli_codec::Registry::new() knows the nineteen UIDs in KNOWN_TRANSFER_SYNTAXES and has no decoder until you register one. Six functions register the six families.

use ocelli_codec::{
    register_htj2k_decoders, register_jpeg2000_decoders, register_jpeg_decoders,
    register_jpegls_decoders, register_jpegxl_decoders, register_native_and_rle_decoders,
    Capability, Registry, RegistryError,
};

fn registry() -> Result<Registry, RegistryError> {
    let mut registry = Registry::new();
    register_native_and_rle_decoders(&mut registry)?;
    register_jpeg_decoders(&mut registry)?;
    register_jpeg2000_decoders(&mut registry)?;
    register_jpegls_decoders(&mut registry)?;
    register_htj2k_decoders(&mut registry)?;
    register_jpegxl_decoders(&mut registry)?;
    Ok(registry)
}

let registry = registry()?;
assert_eq!(registry.capability("1.2.840.10008.1.2.4.90"), Capability::Available);

// desc is a FrameDesc, transfer_syntax_uid the transfer syntax to decode
// and encoded the frame's compressed bytes.
let mut out = vec![0_u8; registry.decoded_output_len(transfer_syntax_uid, &desc)?];
registry.decode(transfer_syntax_uid, encoded, &desc, &mut out)?;

Seventeen are available. Deflated Explicit VR Little Endian deflates the whole data set rather than a frame, PS3.5 A.5, so it is handled by parse_part10 under deviation D-18 and has no frame decoder. JPEG XL JPEG Recompression has no decoder either: jxl-jbr 0.2.1 panics in the DHT branch of JPEG reconstruction, which is jxl-oxide issue 512, so a .111 frame is refused before any byte reaches jxl-oxide. crates/ocelli-codec/tests/registry.rs asserts the nineteen, the seventeen and which two are unavailable.

JPEG-LS frames decode to the same samples as CharLS 2.4.4, the decoder cornerstone3D uses, on every undamaged stream of a generated corpus that CharLS opens, 149 of 150, the other a hand-built stream both refuse. A scan that runs out of data, carries a prediction error no encoder writes, or leaves non-zero or more than 7 bits after its last sample is refused as CodecError::DecoderFailure, and 0xFF fill bytes before EOI are accepted. A damaged scan can read as a valid scan of another image, which no decoder can detect, so not every damaged scan is refused, and some damaged streams that CharLS draws, such as one with a 0x00 byte inserted before EOI, are refused here. An LSE preset other than the defaults is refused as CodecError::UnsupportedPreset, whose JpegLsPreset names the parameter: MaxVal, Reset, PartialDefaultThresholds or ThresholdOrder. A zero MAXVAL, a zero RESET and three zero thresholds select the defaults and decode.

9The LUT chain

DICOM PS3.3 C.11 turns a stored sample into a displayed value in stages. ocelli-pixel implements every decision once and composes the grey scale stages in LutChain.

StageDICOMTypeSpace
1, ModalityPS3.3 C.11.1ModalityTransformStored to Modality
2, VOIPS3.3 C.11.2VoiTransformModality to Display
3, PresentationPS3.3 C.11.6PresentationTransformDisplay to Display
4, ColourPS3.3 C.7.6.3, C.7.9ColorTransformStored or decoded samples to Rgb

Stage 1 uses a Modality LUT Sequence when present and otherwise Rescale Slope and Intercept. Stage 2 uses a VOI LUT Sequence when present and otherwise one selected window pair with a VoiFunction of Linear (C.11.2.1.2), LinearExact (C.11.2.1.3.2) or Sigmoid (C.11.2.1.3.1). Stage 3 resolves inversion exactly once. An explicit Presentation LUT Shape decides alone, and MONOCHROME1 supplies the default only when no shape is declared, so the two sources can never invert twice.

The usual path is open_frame into LutChain::new. Nothing is invented when the file has no window.

use ocelli_core::{Display, Stored};
use ocelli_dicom::{open_frame, parse_part10, WindowInput};
use ocelli_pixel::LutChain;

let parsed = parse_part10(bytes)?;
let opened = open_frame(&parsed, 0)?;

let WindowInput::Transform(voi) = opened.window() else {
    // No VOI LUT Sequence and no window. The caller chooses, Ocelli does not guess.
    return Ok(());
};

let chain = LutChain::new(
    opened.modality().clone(),
    voi.clone(),
    opened.photometric(),
    opened.presentation(),
)?;

let mut display = vec![Display(0.0); stored.len()];
chain.map_into(&stored, &mut display)?;      // stored: Vec<Stored>
let inverted = chain.inverts();

When the file has no window the caller may choose the automatic window instead, and label it as its own choice. AutoWindowPool measures modality values, each frame through its own stage 1, leaves out stored zero and that frame's Pixel Padding Value range, and returns a LINEAR_EXACT window from the 1st to the 99th nearest-rank percentile. series_sample(n) names up to 16 images spread through a series of n, first and last included, and auto_window(&stored, modality, padding) is a pool of one image. This is what the folder viewer does for a series whose images store no window.

use ocelli_core::Stored;
use ocelli_dicom::{open_frame, parse_part10, WindowInput};
use ocelli_pixel::{AutoWindowPool, PhotometricInterpretation, StoredRange, series_sample};

// files: one series in display order. stored_of: that frame's unpacked samples.
// exact: a US or SS padding value as the f32 it is.
let picked = series_sample(files.len())?;
let mut pool = AutoWindowPool::new(picked.len())?;
for at in picked {
    let parsed = parse_part10(&files[at])?;
    let opened = open_frame(&parsed, 0)?;
    if !matches!(opened.window(), WindowInput::Absent)
        || !matches!(opened.photometric(), PhotometricInterpretation::Monochrome1
            | PhotometricInterpretation::Monochrome2)
    {
        continue; // a window in the file is used as it is, and colour has no VOI stage
    }
    let padding = opened.padding().map(|range| StoredRange {
        low: Stored(exact(range.value())),
        high: Stored(exact(range.limit().unwrap_or(range.value()))),
    });
    // A refused frame leaves the pool as it was, so it is skipped.
    let _ = pool.add_frame(&stored_of(&parsed)?, opened.modality(), padding);
}
let window = pool.finish()?;               // window.basis, window.counted
let voi = window.transform(0.0, 255.0)?;   // into each image's own LutChain::new

The stages can be built by hand too. This is the README's example, a LINEAR_EXACT window of centre 100 and width 200 over an output range of 0 to 255.

use ocelli_pixel::{
    LutChain, ModalityTransform, PhotometricInterpretation, PresentationLutEvidence,
    VoiFunction, VoiTransform,
};

let chain = LutChain::new(
    ModalityTransform::new(None, Some(1.0), Some(0.0))?,
    VoiTransform::new(None, &[100.0], &[200.0], 0, VoiFunction::LinearExact, 0.0, 255.0)?,
    PhotometricInterpretation::Monochrome2,
    PresentationLutEvidence::Absent,
)?;
let mut grey = [Display(0.0)];
chain.map_into(&[Stored(50.0)], &mut grey)?;

Every refusal is a PixelError variant. MissingRescale, MismatchedWindowMultiplicity, WindowIndexOutOfRange, InvalidWindow and DestinationLength are typical. A Presentation LUT Sequence is PresentationLutSequenceUnsupported, because applying a shape in its place would answer a different question.

Stage 4 is ColorTransform::resolve and ColorTransform::map_into, with PaletteColorLut for palette colour. It honours the decoder's reported output space, so a frame the codec already converted to RGB is not converted twice. The folder viewer uses DisplayScale, ColourWindow and colour_bytes_into. Its per-channel window and invert follow cornerstone3D 5.8.2, recorded as D-29. The ICC.1:2022 matrix and tone-curve subset parses in IccProfile::parse and attaches once per held frame with ColorTransform::with_icc, before that window. A profile outside the subset keeps device RGB and is named on the page, deviation D-30.

On the GPU, ocelli_render::VoiParams::from_chain turns a chain into HLD section 18.4's uniform for shaders/voi.wgsl. A chain driven by a LUT Sequence has no such uniform, so that path reports unavailable and the CPU path through map_into remains.

10Geometry and spacing

FrameGeometry::derive(&multiframe, frame) resolves Image Position, Image Orientation and Pixel Spacing per frame, then shared, then top level, which is PS3.3 C.7.6.16.1.1's order. It returns an ImagePlane and the PS3.3 C.7.6.2.1.1 index to patient transform.

use ocelli_core::{Index, Pt, World};
use ocelli_dicom::{
    FrameGeometry, MetadataSet, MultiframeMetadata, SpacingRelationship, StackGeometry, StackShear,
};

let metadata = MetadataSet::from_object(parsed.object())?;
let multi = MultiframeMetadata::new(&metadata)?;
let geometry = FrameGeometry::derive(&multi, 0)?;

// x is the column index i, y is the row index j.
let world: Pt<World> = geometry.index_to_world().apply(Pt::<Index>::new(10.0, 20.0, 0.0));

let spacing = geometry.spacing();
match spacing.relationship() {
    SpacingRelationship::ImageOnly => {}
    SpacingRelationship::ImagerAgrees => {}
    SpacingRelationship::Calibrated => { /* spacing.imager_mm() is kept as evidence */ }
}

match StackGeometry::derive(&multi)?.shear() {
    StackShear::AxisAligned { step_mm } => {}
    StackShear::Sheared { max_offaxis_mm } => {}
    StackShear::NotApplicable => {}
}

A Pt<World> and a Pt<Index> are different types, so a transform cannot be handed a point from the wrong space. World is the LPS patient system in millimetres.

Stack shear is measured from the geometry, never read from Gantry/Detector Tilt (0018,1120), which is Type 3 and nominal. Non uniform frame spacing, non parallel frames and coincident frames are refused rather than averaged, because rendering them as uniform distorts geometry in a way no measurement tool flags.

Pixel Spacing and Imager Pixel Spacing stay distinct, PS3.3 10.7.1.1. They are the same when the image has not been corrected for geometric magnification, and differ when it has been corrected or calibrated. ocelli_geom::select_calibration names the source it used, so a measurement never reports one as the other.

use ocelli_geom::{select_calibration, CalibrationRequest, SpacingMm};

let calibration = select_calibration(CalibrationRequest {
    pixel_spacing: None,
    imager_spacing: Some(SpacingMm { row: 0.2, column: 0.2 }),
    estimated_radiographic_magnification_factor: Some(2.0),
    ultrasound_delta: None,
    manual: None,
})?;
let source = calibration.source.name();     // "imager-spacing"
let mm = calibration.spacing;               // patient spacing

The order is pixel spacing, then imager spacing with the magnification factor, then ultrasound deltas, then a manual pair. A present but invalid source is an error and does not fall through.

ocelli_viewport::link links two viewports from their planes. same_frame_of_reference is true only when both Frame of Reference UIDs are present and equal, so a missing UID links nothing. closest_coplanar answers the index in a target stack whose Image Position (Patient) is nearest the source's, keeping the lower index on a tie, and is LinkError::NotCoplanar when the absolute dot product of the source normal and the shown target normal is not above COPLANAR_DOT, 0.9. reference_segment answers where the source plane cuts the target, as two points in the target's index space with the first pixel centre at 0, and is LinkError::Parallel when the absolute dot product is above 1 - PLANE_EPSILON. closest_coplanar is LinkError::Degenerate when no distance is finite, which includes an empty stack. reference_segment is LinkError::Degenerate for a point that is not finite and for a target with a zero spacing on its single row or column. The two constants are cornerstone3D 5.8.2's. SyncScene uses the same UID rule.

use ocelli_viewport::link::{
    closest_coplanar, reference_segment, same_frame_of_reference, FrameOfReferenceUid, LinkError,
};

if same_frame_of_reference(Some(&source_uid), Some(&target_uid)) {
    let next = closest_coplanar(&source_plane, &shown_plane, &target_planes)?;
    match reference_segment(&source_plane, &target_planes[next]) {
        Ok((start, end)) => { /* column x and row y in the target's index space */ }
        Err(LinkError::Parallel) => {}
        Err(_) => {}
    }
}

PS3.3 10.7.1.1 says a Pixel Spacing that has not been calibrated for geometric magnification has the same values as the Imager Pixel Spacing, so an equal pair takes the imager path. The pair is equal when both halves agree within ocelli_core::SPACING_EQUALITY_MM, the same rule ImagerAgrees uses. With a magnification factor the source is "imager-spacing". With none it is "detector", the imager spacing at the detector plane and not a patient spacing. A factor that is present but not finite, or not strictly positive, is refused, as it is without Pixel Spacing. A Pixel Spacing that differs decides on its own.

11Measurement

ocelli-geom holds the measurement mathematics, generic over the coordinate space so a length in index space and a length in patient space cannot be mixed.

use ocelli_core::{Pt, World};
use ocelli_geom::{angle_at, distance, polygon_area, roi_statistics};

let a = Pt::<World>::new(0.0, 0.0, 0.0);
let b = Pt::<World>::new(3.0, 4.0, 0.0);
let mm = distance(a, b)?;

let stats = roi_statistics(&samples, area_mm2)?;   // count, mean, sd, min, max, area

The full set is distance, length, polyline_length, height, angle_at, cobb, bidirectional, rectangle, circle, ellipse, polygon_area, spline_point, hit_segment, project_onto_segment and project_onto_plane. Statistics are roi_statistics and histogram. PET SUV is suv_bw, suv_lbm and suv_bsa. Refusals are GeomError and SuvError.

Which samples a region holds is region_contains and region_bounds, over a RegionShape of a rectangle, an axis-aligned ellipse or a polygon in index space. A sample belongs to a region when its pixel centre, the index point (c, r), is inside the shape or on its boundary, and the polygon rule is the same even-odd and on-edge rule ocelli-seg paints a contour with. polygon_crosses_itself says whether a ring crosses or touches itself anywhere but at the shared vertex of two neighbouring edges.

livewire_path, livewire_mask and redact_rect live here too.

12Cache and volume

ocelli_cache::Lru<K, V> is HLD section 20's budgeted cache. A value reports its size through the Budgeted trait. The CacheTier is Encoded, Decoded or Gpu, each with its own budget and pressure signal.

use ocelli_cache::{Admission, Budgeted, CacheTier, Lru, PressureBand};

struct Frame(Vec<u8>);
impl Budgeted for Frame {
    fn bytes(&self) -> usize { self.0.len() }
}

let mut cache: Lru<u64, Frame> = Lru::new(CacheTier::Decoded, 64 * 1024 * 1024);
let Admission { evicted, displaced, refused } = cache.insert(7, Frame(bytes));
let band = cache.pressure().band();     // Low, Elevated or Critical

An eviction, a replacement and a refusal are three different outcomes, and Admission is the only thing that tells them apart, so it is #[must_use]. The bands sit at one half and nine tenths of the budget. The value types in the library are DecodedFrame and Brick in ocelli-cache and Volume in ocelli-volume.

Beside DecodedFrame sits CommittedFrame, F-231's value for the wasm session's own cache: the columns and rows a commit named and the stored samples, with no description and no plane, because the session never receives those. ImageCache<V> holds either value under the same Lru, the same events and the same stale rule, and the committed tier adds is_resident, a query that moves no recency and removes no mismatch.

Leaving a series releases all of its frames in one call, and leaving a volume releases every brick of every level. Neither is an eviction. release_series returns one Released event for the series, which the ring carries as cache.released, and nothing when the series held nothing. release_volume returns a ReleaseSummary, because volumes and bricks have no ring event.

use ocelli_cache::{BrickCache, CacheEvent, ImageCache, SeriesId, VolumeId};
use ocelli_volume::{VolumeCache, VolumeKey};

let events = images.release_series(SeriesId(5));       // images: ImageCache
for event in events.events() {
    if let CacheEvent::Released { series, frames, bytes } = event {
        // one event for the whole series, `bytes` left the budget
    }
}
let gone = bricks.release_volume(VolumeId(2));          // bricks: BrickCache
let _ = (gone.entries, gone.bytes);                     // every level of volume 2
let _ = volumes.remove(&VolumeKey { series: SeriesId(5) }); // volumes: VolumeCache

A key is the caller's slot, and it says nothing about which bytes fill it. So ImageCache keeps beside each frame the ContentId of the bytes it was decoded from, FNV-1a 64 over the length-prefixed SOP Instance UID, transfer syntax UID and encoded bytes. A lookup presents a FrameSource, and it is a hit only when that id, the stored pixel description and the image plane all equal the held frame's. Anything else removes the held frame and answers Stale with the bytes that left, without an event, so a re-processed object put in the same slot is never served the old frame. The decoded tier saves a decode and never a fetch, so whether the bytes are fresh is the transport's question, which DicomwebClient's cache option answers.

use ocelli_cache::{ContentId, FrameKey, FrameLookup, FrameSource, ImageCache, SeriesId};

let key = FrameKey::new(SeriesId(5), 0, 0);
let content = ContentId::of(sop_uid, transfer_syntax_uid, &encoded);
let _ = images.insert(key, content, frame);              // images: ImageCache
let source = FrameSource { content, description, plane };
match images.get(&key, &source) {
    FrameLookup::Hit(frame) => {}                        // decoded from these bytes
    FrameLookup::Miss => {}
    FrameLookup::Stale { bytes } => {}                   // other bytes or metadata, now removed
}

The cache has no study. A study is released by whoever owns it calling release_series for each of its series, VolumeCache::remove for each of its volumes and release_volume for each of its bricked volumes. This folder viewer releases by file instead: opening another folder or the synthetic study sends the left folder's ids to POST /forget, which drops each file and every frame of it from the local process.

The page keys every grey it keeps by the file object a folder choice gave it, so choosing the same folder again reads the files again. A file rewritten on disk after the folder was opened is found when the window regains focus, when the page becomes visible again, when a series is selected or when another viewport becomes active, by reading one byte of each file of the active series, one at a time. A file the browser refuses to read is forgotten through POST /forget, and its viewport, or its tile in Four images, reads "This file changed or was removed on disk after the folder was opened. Open the folder again to see it." A modification time that moved counts as a change even when the bytes are the same. A rewrite that keeps the modification time is not detected, and the held image stays until the folder is opened again. A change is noticed at the next focus, return to the page, series selection or change of active viewport. Only Chromium was measured.

ocelli_volume::group_volumes splits decoded frames by frame of reference and orientation together, so a localiser mixed with axials is two candidates. Volume::assemble then refuses a candidate that is not one volume.

use ocelli_volume::{group_volumes, FrameOfReferenceUid, Volume};

let candidates = group_volumes(frames                    // Vec<DecodedFrame>
    .into_iter()
    .map(|frame| (FrameOfReferenceUid(uid.clone()), frame))
    .collect());
for candidate in candidates {
    let volume = Volume::assemble(candidate)?;           // VolumeError on refusal
}

Spacing comes from Image Position Patient projected on the slice normal. Slice Thickness, Spacing Between Slices, Slice Location and the tilt tag are not read anywhere in that crate. A sheared stack is VolumeError::ShearedVolume for Volume and is kept by TiltedVolume. Reslicing, slab and fusion are on the More page.

13Tiers A, B and C

Every rendering or compute feature declares an answer for three tiers.

Tierocelli_render::TierWhat it is
ATier::AWebGPU. Compute shaders, storage buffers, 3D textures.
BTier::BWebGL2 through wgpu's downlevel profile. Fragment shaders only, no compute.
CTier::CpuCPU, deviation D-07. A stack viewport renders, windows, scrolls and measures through ocelli-pixel.
 
use ocelli_render::{resolve, Tier};

let request = Tier::from_override_str("auto");      // "a", "b", "cpu" or "auto"
let resolution = resolve(request, &mut clock).await; // clock: monotonic nanoseconds
match resolution.caps.tier {
    Tier::A => {}
    Tier::B => {}
    Tier::Cpu => {}
}
let compute = ocelli_render::compute_available(&resolution.caps);

resolve never fails. A failure of detection is a resolved tier with a recorded reason in resolution.evidence. A measured fill rate decides first, then the adapter type, then the renderer string, and a software rasteriser resolves tier C rather than pretending to be tier B. Natively the override comes from OCELLI_TIER. In a browser the shell passes it, because reading a query parameter is DOM work.

A feature that cannot run on the resolved tier reports unavailable. It never quietly produces a different result. In Rust that is ComputeError::Unavailable { required, resolved } or a feature's own TierCUnavailable variant. Across the boundary it is ErrorCode::Unavailable, stable number 700. In TypeScript a tier answer is "available", "degraded" or "unavailable" from TIER_AVAILABILITY.

On tier C, stack drawing is CpuRaster. Fusion, volume ray casting and the segmentation overlays return unavailable there before reading a sample, and the CPU MPR path is present_cpu_plane.

14Annotations as SR

Decision D13 says the annotation type is a DICOM SR content tree. A measurement is not drawn first and exported later. It is a tree of coded content items from the start, so it is interoperable by construction.

A content item is a plain object with a relationship, a coded concept, children and a valueType of CONTAINER, TEXT, NUM, CODE, UIDREF, IMAGE, SCOORD or SCOORD3D, PS3.3 C.17.3. A coordinate's graphic is POINT, POLYLINE, CIRCLE or ELLIPSE, PS3.3 C.18.6.1.2, and an ellipse takes four points, the major axis then the minor. An IMAGE item may carry frame, its Referenced Frame Number counted from 1. contentTree(root) validates and copies a whole tree, and one bad node returns null.

import { contentTree, provenanceItems } from "@ocelli/core";

const length = contentTree({
  relationship: null,
  valueType: "NUM",
  concept: { scheme: "SCT", value: "410668003", meaning: "Length" },
  number: 12.5,
  unit: "mm",
  children: [
    ...(provenanceItems("Length", "0.1.0", null, "reader") ?? []),
  ],
});
if (length === null) throw new Error("the tree was refused");

Annotation state is immutable. Each call returns a new state or null for a refusal, and undo and redo are stacks on that state.

import {
  annotationsForFrame, createAnnotationState, putAnnotation, redoAnnotation, undoAnnotation,
} from "@ocelli/core";

let state = createAnnotationState();
state = putAnnotation(state, "m1", frameOfReferenceUid, length) ?? state;
const onThisFrame = annotationsForFrame(state, frameOfReferenceUid);
state = undoAnnotation(state) ?? state;
state = redoAnnotation(state) ?? state;

A tree saves two ways. persistMeasurements(items) returns a JSON string and loadMeasurements(text) reads it back. writeTid1500(items, source) writes a TID 1500 Comprehensive 3D SR, SOP class 1.2.840.10008.5.1.4.1.1.88.34, through dcmjs, and readTid1500(bytes) reads it.

import { readTid1500, writeTid1500 } from "@ocelli/core";

const bytes = writeTid1500([length], {
  study: studyUid,
  series: seriesUid,
  sopClass: "1.2.840.10008.5.1.4.1.1.2",   // the referenced image's class
  sopInstance: imageUid,
});
const back = bytes === null ? null : readTid1500(bytes);

writeTid1500Groups(groups, source) writes a whole TID 1500 document of TID 1410 measurement groups. Each root is a (125007, DCM, "Measurement Group") container of any value type, such as an Image Region SCOORD with the IMAGE it was drawn on. source carries the patient and study attributes copied from the images, Content Date and Content Time, the evidence and the documents it replaces, which go in Predecessor Documents Sequence. readTid1500Groups(bytes) returns the groups, the predecessors and a count of groups it could not read. It decodes text in the file's own Specific Character Set: no value or ISO_IR 6, ISO_IR 100, 101, 109, 110, 126, 127, 138, 144, 148, 166, 192 and 203, GB18030 and GBK. It counts a group unread when that set uses code extensions or is another one. A file it cannot walk to that element, such as a deflated one, has its text decoded only when it carries no Specific Character Set, and otherwise every group is counted unread. writeKeyObjects(references, source) writes one Key Object Selection whose references are IMAGE items for an image, each with an optional frame, WAVEFORM items for a waveform and COMPOSITE items for any other object, and readKeyObjects(bytes) reads them back. Every reference must also be in source.evidence, or nothing is written. The folder viewer's Save marks is built on these four.

Save marks uses only the open folder and documents read into it with Load marks. Opening another folder clears its marks, key images and remembered documents.

The SVG drawing layer is createAnnotationLayer(svg, listener). It draws marks and does not own the tree. Key object selection and secondary capture are on the More page.

15Errors

Each Rust crate returns its own typed error, and none of them keeps patient data. ParseError, FrameOpenError, FrameGeometryError, CodecError, RegistryError, PixelError, GeomError, VolumeError and ComputeError name a failure class, never a value.

A Rust panic poisons the wasm instance, and HLD section 23 says it must not be reused. The panic hook writes a record into linear memory, and the shell reads it after the trap without calling any export.

import {
  CORE_OK, describeError, ERROR_CODE, fatalFromPanic, isUsable, nextStatus, readPanicRecord,
} from "@ocelli/core";

let status = CORE_OK;
const ptr = wasm.panic_record_ptr();      // cache both at instantiation
const len = wasm.panic_record_len();

// After a trap:
const record = readPanicRecord({ memory }, ptr, len);
status = nextStatus(status, fatalFromPanic(record));
if (!isUsable(status)) {
  // Tear down the worker and rebuild from the shell's own checkpoint.
  show(status.message);
}

describeError(ERROR_CODE.Unavailable);  // the human text. Match on the code, never the text.

nextStatus is a latch. Once fatal, a status stays fatal, so a retry can never mark a poisoned instance as healthy. Event records decode through decodeRecord, with SEVERITY and LOG_LEVEL. DicomwebError keeps a code and an HTTP status and nothing else. OcelliError is the shell error. Its string codes are not the numeric ring codes.

16Testing and the oracle

Tests derive from the DICOM standard or the oracle, never from reading the implementation. Every function that does pixel arithmetic has a fixture with hand computed values that cites its PS3.3 section. The LUT chain's fixtures follow HLD section 18.3.

The oracle in tools/oracle renders every applicable corpus row through cornerstone3D 5.8.2 under headless Chromium and writes reference pixels with a metadata sidecar. The cornerstone3D packages are pinned to that exact version. The HLD names v5.8.9, which does not exist, and that is deviation D-11.

bin/ocelli.sh oracle             # the reference half (needs a GPU)
bin/ocelli.sh compare            # identity, then the mutation catalogue
bin/ocelli.sh compare produce --reference REF --candidate CANDIDATE --corpus ROOT
bin/ocelli.sh compare gate    --reference REF --candidate CANDIDATE --out OUT
bin/ocelli.sh gate oracle        # render, check the event catalogue, then compare

compare produce writes one Ocelli image per view from the real decode, a LutChain applied through CpuRaster, and Volume::reslice_nearest, and compare gate judges it against HLD section 25.1's tolerances. Colour, palette and YBR images are written and not scored yet. A declared mutation catalogue applied to real reference frames proves that the comparator catches the defects it is meant to catch.

bin/ocelli.sh bench --compare-cornerstone --pseudo <local-root> measures this local folder viewer and a pinned cornerstone3D page on the same inputs. It checks actual CT canvas pixels before timing either side and records cold and warm conditions, defaults, and every product process. The native CPU canvas and browser WebGL paths do different work. The record describes those limits, and docs/lld/benchmarks.md documents the instrument. An equipped comparison remains required before making a cost claim.

Ocelli claims a measured divergence, never bit exact reproduction, which is decision D14. The corpus lives outside git behind corpus/manifest.tsv, and no patient data enters the repository.
