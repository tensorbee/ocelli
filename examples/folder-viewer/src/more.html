Images More Use

More than this image

The image page shows one slice of one series. The library does more than that page draws. This page names each of those features, says what it is for, where it lives, how to call it, and whether it is built.

There is no picture on this page and no stand-in result. The code below is real API from this repository, so it shows the calls and not their output. The example viewer started with npm run dev is where the library's controls run, and it labels a control unavailable when that control is not built.

Each feature carries one of three marks. Implemented means the library code exists with tests. Partial means part of it exists and the rest is named. Not yet means there is no code. A tier line says what tiers A (WebGPU), B (WebGL2) and C (CPU) do. A tier that cannot run a feature reports unavailable and never draws something else instead.

Overlay planes and display shutters

Implemented as a reader. Nothing draws it yet.

An overlay plane is a one bit graphic stored beside the image, such as a marker or a region of interest drawn by the modality, PS3.3 C.9.2. A display shutter masks part of the image that should not be shown, often the collimated edge of a radiograph, PS3.3 C.7.6.11.

Lives in ocelli-dicom, crates/ocelli-dicom/src/overlay.rs. read_overlays returns an OverlaySet for one frame.

use ocelli_dicom::{parse_part10, read_overlays, ShutterShape};

let parsed = parse_part10(bytes)?;
let set = read_overlays(&parsed, 0)?;          // frame 0

for plane in set.planes() {
    let group = plane.group();                   // an even group from 0x6000
    let kind = plane.overlay_type();             // OverlayType::Graphics or Roi
    let on = plane.bit(row, column);             // 1-based image pixel
}

if let Some(shutter) = set.shutter() {
    let hidden = shutter.hides(row, column);     // shapes combine by intersection
    for shape in shutter.shapes() {
        match shape {
            ShutterShape::Rectangular { left, right, upper, lower } => {}
            ShutterShape::Circular { center_row, center_column, radius } => {}
            ShutterShape::Polygonal { vertices } => {}
            ShutterShape::Bitmap { group } => {}
            _ => {}                              // non_exhaustive
        }
    }
}
let grey = set.presentation_value();             // Shutter Presentation Value, when present

Tiers A, B and C do not draw this module. The reader does not decode Pixel Data. The example page posts a synthetic object and prints whether one pixel is set and whether the shutter hides it.

Interpolation between pixels and between slices

Partial. In-plane nearest and linear are built. Blending two stack slices is not.

When an image is zoomed, each screen pixel falls between stored pixels. Nearest shows the closest stored value, which keeps edges hard. Linear blends the four neighbours, which looks smoother but is no longer a stored value. A reader should know which one is on.

Lives in ocelli-render, crates/ocelli-render/src/interpolation.rs. Interpolation is Nearest or Linear, and available(mode, tier) answers before a draw.

use ocelli_render::{available, Interpolation, Tier};

let mode = Interpolation::Linear;
if available(mode, resolution.caps.tier) {
    graph.set_stack_interpolation(&ctx, viewport, mode)?;   // tiers A and B
}
raster.set_interpolation(mode.mode())?;                       // tier C, CpuRaster

Sampling between two slices is a volume operation. Volume::reslice takes a fractional slice index and reads it through the volume's trilinear sample, shown under MPR below. A stack mode that blends slice n with slice n + 1 on screen is not built.

Nearest and linear are available on tiers A, B and C. Linear on an orthographic plane is refused rather than drawn as nearest.

Reference line and reference cursor

Implemented as segment geometry. Projection is the caller's.

A reference line shows where the slice in one viewport cuts the image in another, so a reader can tell which axial level a coronal line is at. A reference cursor marks the same patient point in every viewport.

Lives in @ocelli/core, packages/core/src/crosshair.ts and packages/core/src/intersection.ts, where overlayGrid lives. The functions take a point already projected into viewport pixels and return segments for the SVG layer.

import { crosshairLines, overlayGrid, referenceCursor, referenceLines } from "@ocelli/core";

// x and y are viewport pixels. Null when the point is outside the viewport.
const lines = referenceLines(x, y, width, height);   // [horizontal, vertical] Segments
const cursor = referenceCursor(x, y, width, height); // { x, y } or null
const cross = crosshairLines(x, y, width, height);   // the same two segments
const grid = overlayGrid(2, 2, width, height);       // interior lines of a layout grid

for (const { x0, y0, x1, y1 } of lines ?? []) {
  // append an SVG line element
}

These functions do not project a plane and do not read a frame of reference. The projection from another series comes from the geometry chapter of Use or from SyncScene below. This shell code runs the same on every tier.

Several series at once

Partial. Slice sync by patient point is built. Linked scroll, synced window and priors are not.

Reading often means two series side by side: a current scan beside a prior, or two sequences of the same MRI. Scrolling one should move the other to the same anatomy, and a window change may apply to both.

Lives in ocelli-volume as HeldPlane and in ocelli-viewport as sync::SyncScene. A scene moves every viewport that shares the source's Frame of Reference UID onto one patient point.

use glam::DVec3;
use ocelli_core::{Pt, World};
use ocelli_viewport::sync::SyncScene;
use ocelli_volume::{FrameOfReferenceUid, HeldPlane};

let mut scene = SyncScene::new();
let plane = HeldPlane {
    anchor: Pt::<World>::new(0.0, 0.0, 0.0),  // world point of index 0
    normal: DVec3::new(0.0, 0.0, 1.0),
    spacing_mm: 2.5,
    index: 0.0,
};
scene.register(1, Some(FrameOfReferenceUid(uid.clone())), plane);
scene.register(2, Some(FrameOfReferenceUid(uid.clone())), other_plane);

// Viewport 1 moved to this point. Every peer with the same UID follows.
for change in scene.set_point(1, point)? {
    let (id, index) = (change.id, change.index);
}

A different Frame of Reference UID stays where it is, and a refused point is SyncError::Unavailable with no slot written. attachSideBySide(ocelliElement, neighbour) in @ocelli/core pairs an Ocelli element with an element another library owns and enables the seam, which is the migration case rather than a second series.

Not built: linked scroll and synced window as shell features, and prior study lookup. The example page reads Prior studies, Linked scroll and Synced window unavailable.

MPR

Implemented in the library. The example page reads it unavailable.

Multiplanar reformation rebuilds sagittal, coronal or any oblique plane from a stack of axial slices, so anatomy can be seen in the plane that shows it best. It depends on correct spacing and orientation, which is why a sheared stack is refused rather than straightened.

Lives in ocelli-volume, crates/ocelli-volume/src/ortho.rs, with presentation in ocelli-render, crates/ocelli-render/src/ortho.rs.

use ocelli_volume::{ObliquePlane, OrthoPlane, PlaneSample, Volume};

let volume = Volume::construct(candidate)?;

let axial    = volume.reslice(OrthoPlane::Axial    { slice: 10.5 })?;   // fractional is allowed
let sagittal = volume.reslice(OrthoPlane::Sagittal { column: 256.0 })?;
let coronal  = volume.reslice(OrthoPlane::Coronal  { row: 256.0 })?;

let oblique = volume.reslice_oblique(ObliquePlane {
    origin, row, column,            // Pt<World> and two DVec3 directions
    columns: 512, rows: 512,
    column_mm: 0.7, row_mm: 0.7,
})?;

for sample in &axial.samples {
    match sample {
        PlaneSample::Present(value) => {}
        PlaneSample::Absent => {}  // a slice not landed or outside, never stored zero
    }
}
use ocelli_render::{present_cpu_plane, present_plane};

present_plane(tier, &axial, |samples| upload(samples))?;                      // tiers A and B
present_cpu_plane(&mut raster, &view, &presentation, &axial, quality, &mut out)?; // tier C

Tiers A and B present through present_plane and RenderGraph::show_ortho. Tier C presents through present_cpu_plane into CpuRaster. An absent sample or a raster refusal writes nothing.

Slab

Partial. Built on tiers A and B. Tier C is unavailable.

A slab collapses a thick block of slices into one image. Maximum intensity projection makes contrast filled vessels or lung nodules stand out, minimum intensity projection shows airways, and an average reduces noise.

The plane and samples live in ocelli-volume, crates/ocelli-volume/src/slab.rs. The reduction is a shader in ocelli-render, chosen by BlendMode.

use ocelli_render::BlendMode;
use ocelli_volume::OrthoPlane;

let frame = volume.slab_plane(OrthoPlane::Axial { slice: 40.0 })?;
let image = volume.slab_samples(frame, 10.0)?;            // thickness in mm

graph.show_slab(&ctx, &adapter, viewport, &image, BlendMode::Mip)?;
// BlendMode::MinIp and BlendMode::Average are the other two reductions.

MIP, MinIP and average reduce stored samples and then apply the one existing VOI stage. Tiers A and B draw it. Tier C returns unavailable, because there is no CPU reducer.

Volume rendering

Partial. Built on tiers A and B. Tier C is unavailable.

Volume rendering casts a ray through the whole volume and accumulates colour and opacity, so a reader sees bone, vessels or an organ surface in three dimensions. It is for orientation and communication, not for measurement.

Lives in ocelli-render, crates/ocelli-render/src/graph.rs, with OpacityTable in opacity.rs, ShadeWeights in shade.rs and ClipPlane in clip.rs.

use ocelli_render::{volume_ray_admission, OpacityPreset, OpacityTable};

// Answer before any sample is read.
volume_ray_admission(tier, ready_bricks, sampled_limit)?;   // Err(TierCUnavailable) on tier C

let report = graph.sync_volume(&ctx, &adapter, volume_id, &volume)?;  // upload ready bricks
graph.bind_volume_ray(&ctx, &adapter, viewport, source)?;           // a VolumeRaySource
graph.set_opacity(&ctx, viewport, &OpacityTable::preset(OpacityPreset::Ramp))?;
graph.set_shade(&ctx, viewport, &weights)?;
graph.set_clip_planes(&ctx, viewport, &planes)?;
let outcome = graph.tick(&ctx);

Tiers A and B run the fragment ray. Tier C returns TierCUnavailable from volume_ray_admission before a sample is read and writes no colour. There is no CPU ray and the ray has no MIP body.

Fusion

Partial. Built on tiers A and B. Tier C is unavailable.

Fusion lays one modality over another in the same patient space, most often PET colour over CT grey, so uptake can be placed on anatomy. The two volumes must share a frame of reference, or the overlay is in the wrong place.

The plane lives in ocelli-volume, crates/ocelli-volume/src/fusion.rs. The draw lives in ocelli-render, crates/ocelli-render/src/fusion.rs.

use ocelli_render::{FusionError, FusionRequest};
use ocelli_volume::{plane_from_ortho, world_on_plane, OrthoPlane};

let Some(plane) = plane_from_ortho(&ct, OrthoPlane::Axial { slice: 60.0 }) else { return };
let corner = world_on_plane(&plane, 0, 0);       // Pt<World> of one plane pixel

let request = FusionRequest {
    volume_a: &ct,  frame_a: &ct_frame,  chain_a: &ct_chain,  opacity_a: 1.0, colormap_a: None,
    volume_b: &pet, frame_b: &pet_frame, chain_b: &pet_chain, opacity_b: 0.5, colormap_b: Some(hot.as_slice()),
    plane: &plane,
};
match graph.show_fusion(&ctx, &adapter, &request) {
    Ok(()) => {}
    Err(FusionError::FrameMismatch) => {}     // the two UIDs differ
    Err(FusionError::TierCUnavailable) => {}
    Err(other) => {}
}

Tiers A and B draw it when a float sample format and the Rgba16Float target can be bound, and otherwise return FusionError::Unavailable. Tier C returns FusionError::TierCUnavailable before a sample is read.

Histogram

Partial. The function is built. No histogram view exists.

A histogram counts how many pixels fall in each value range. It helps choose a window, shows whether an image is clipped, and summarises a region.

Lives in ocelli-geom, crates/ocelli-geom/src/stats.rs. The counts go into a buffer you own.

use ocelli_geom::{histogram, roi_statistics};

let mut counts = [0_u32; 256];
let range = histogram(&samples, &mut counts)?;   // samples: &[f64]
let (low, high, bin) = (range.min, range.max, range.width);

let stats = roi_statistics(&region, area_mm2)?;   // count, mean, sd, min, max, area

This is plain arithmetic and runs anywhere. A value on an interior edge belongs to the higher bin. No viewport or shell control draws a histogram. The example page reads Histogram unavailable, and the HLD's GPU histogram pass is tier A only.

Metadata browser

Partial. The data model is built. No browser view exists.

A metadata browser lists every attribute of an instance by tag, keyword and value. It answers questions the image cannot, such as which kernel was used or why the spacing looks wrong.

Lives in ocelli-dicom, crates/ocelli-dicom/src/metadata.rs. MetadataSet holds tags in order, and each MetadataElement carries a VR and a typed MetadataValue.

use ocelli_dicom::{MetadataSet, MetadataValue, Tag};

let metadata = MetadataSet::from_object(parsed.object())?;

for (tag, element) in metadata.iter() {
    let text = element.semantic_text();       // Option<Vec<&str>>
    match element.value() {
        MetadataValue::Sequence(items) => {}  // nested MetadataSet values
        MetadataValue::PersonNames(names) => {}
        MetadataValue::BulkDataUri(uri) => {}
        _ => {}
    }
}
let modality = metadata.get(Tag(0x0008, 0x0060));

The same model is what QIDO-RS JSON parses into. The image page has a Headers panel. The example viewer reads Metadata browser unavailable.

One to one

Not yet.

One to one shows each stored pixel as exactly one screen pixel, so nothing is resampled and fine texture is seen as acquired.

There is no code for it. A Zoom command in @ocelli/core scales the camera by a factor, and nothing computes the factor that maps one stored pixel to one device pixel.

import { packCommands, viewportId } from "@ocelli/core";

// What exists: an explicit zoom factor. It is not a one to one mode.
packCommands(viewportId(1), [{ kind: "Zoom", factor: 2 }]);

The example page reads One to one unavailable.

Preferences

Not yet.

Preferences keep a reader's choices between sessions, such as default window presets, tool bindings and hanging layouts.

There is no preferences module in the crates or packages. The session state that does exist is the viewport snapshot, which restores a viewport after a fault and is not a preference store.

import { parseSnapshot } from "@ocelli/core";

// What exists: one viewport's state as copied JSON, for recovery.
const parsed = parseSnapshot(session.snapshot());

The example page reads Preferences unavailable.

Worker decode and the wasm path

Partial. Fetch, hand-off and the worker pool are built. Decoding those bytes in the worker is not.

In the browser path, the DICOM bytes go to a worker that owns the wasm core, and decoded pixels stay there. The main thread keeps the DOM responsive. This folder viewer posts each file once while the local process holds it, and posts it again after eviction or a restart. It is still not the wasm path.

Lives in @ocelli/core: postWadoInstance in instance-bytes.ts, holdSessionBytes in bulk.ts, and openDecodePool in pool.ts.

import {
  DEFAULT_DECODE_WORKERS, MAX_DECODE_WORKERS, holdSessionBytes, openDecodePool, postWadoInstance,
} from "@ocelli/core";

// Main thread: one WADO-RS instance, posted to the worker as a transfer.
await postWadoInstance({
  studiesServiceUrl, wadoUriUrl, fetch: globalThis.fetch.bind(globalThis),
  studyUid, seriesUid, instanceUid,
  post(bytes, boundary) {
    worker.postMessage({ type: "instance", bytes: bytes.buffer, boundary }, [bytes.buffer]);
  },
});

// Worker: copy the body into the session's one bulk slot. It is not parsed here.
ticket = holdSessionBytes(wasm, new Uint8Array(message.bytes), ticket);

// Several decode workers, each its own wasm instance. No SharedArrayBuffer.
const pool = openDecodePool(owner, DEFAULT_DECODE_WORKERS, (index) => new Worker(url));
pool?.close();

Built: the bounded fetch, the hand-off, the bulk slot, and a pool of one to MAX_DECODE_WORKERS workers with threadingEscalation() fixed at "stable". Not built: decoding that envelope in the worker, its frame cache and a render of that frame. The example worker publishes one stored sample to prove the path.

Documents

Implemented in @ocelli/core.

A measurement is useful beyond the session only if another system can read it. DICOM SR TID 1500 carries measurements, a Key Object Selection flags the images that matter, and a Secondary Capture stores a rendered picture as an image.

Lives in packages/core/src: tid1500.ts, measurement-persist.ts, annotation-state.ts, tid2010.ts and secondary-capture.ts. The tree they share is sr.ts.

TID 1500 measurement report

import { readTid1500, writeTid1500 } from "@ocelli/core";

// SOP class 1.2.840.10008.5.1.4.1.1.88.34, one NUM per root item.
const bytes = writeTid1500(items, { study, series, sopClass, sopInstance });
const items2 = bytes === null ? null : readTid1500(bytes);

Save, load, undo

import {
  createAnnotationState, loadMeasurements, persistMeasurements,
  putAnnotation, redoAnnotation, undoAnnotation,
} from "@ocelli/core";

const text = persistMeasurements(items);            // JSON string, or null
const loaded = text === null ? null : loadMeasurements(text);

let state = createAnnotationState();
state = putAnnotation(state, "m1", frameOfReferenceUid, tree) ?? state;
state = undoAnnotation(state) ?? state;
state = redoAnnotation(state) ?? state;

Key Object Selection

import { readKeyObject, writeKeyObject } from "@ocelli/core";

// TID 2010, SOP class 1.2.840.10008.5.1.4.1.1.88.59.
const kos = writeKeyObject({
  title: "Key image",
  study, series, instance,              // the new document's UIDs
  referencedClass, referencedInstance,  // the image being flagged
});
const doc = kos === null ? null : readKeyObject(kos);   // title and the reference

Secondary capture

import { readSecondaryCapture, writeSecondaryCapture } from "@ocelli/core";

// SOP class 1.2.840.10008.5.1.4.1.1.7, 8-bit MONOCHROME2, your display bytes.
const sc = writeSecondaryCapture({ study, series, instance, columns, rows, pixels });
const image = sc === null ? null : readSecondaryCapture(sc);

These functions write and read documents and do not draw, so tiers do not apply. The key image flag on the image page is only a mark in this session. It does not write a Key Object Selection and it is not saved.
